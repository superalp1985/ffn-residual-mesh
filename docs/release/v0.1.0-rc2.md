# FFN Residual Mesh v0.1.0-rc2

## Release Title

**FFN split/merge runtime: trade compute for bandwidth on small-VRAM GPUs**

## Release Summary

FFN Residual Mesh introduces a layered FFN base/residual split designed for bandwidth-bound local inference. During cold start, the original quantized weights are scanned once and compiled into finite base formulas, partial sums, residual tiles, scales, and fallback metadata. During normal execution, the center GPU receives residual tiles and performs the dense arithmetic, nonlinear merge, SwiGLU, and down projection.

The project is intentionally not marketed as FLOPs reduction. Its success condition is higher GPU work per transferred byte, lower GPU waiting, and better copy/compute overlap.

## Core Mathematical Contract

For gated FFN:

```text
g = W_gate x
u = W_up x
y = W_down (SiLU(g) * u)
```

The split is:

```text
W_gate = B_gate + R_gate
W_up   = B_up   + R_up
g = Eval(B_gate, x) + Eval(R_gate, x)
u = Eval(B_up, x)   + Eval(R_up, x)
y = W_down (SiLU(g) * u)
```

The gate/up terms are merged before the nonlinear operation. Centered-block, radix, and hierarchical integer formulas retain the required cross terms; complete residuals preserve exact reconstruction in the selected quantized domain. Approximate residual paths are isolated, measured, and must retain an exact GPU fallback.

## MiniMax H3 / ComfyUI Result

For the default 832x480, 124-frame, 20-step workload with 8 TeaCache real steps:

- Exact gate/up base return: approximately 839.8 MiB per real step.
- At 1 Gb/s: the phone branch remains critical, with an estimated total around 116.7 seconds.
- At 10 Gb/s: the phone branch is hidden under the modeled GPU branch, with an estimated total around 114.2 seconds.
- Hidden-return approximation: approximately 157.5 MiB per real step, but it is not algebraically exact.

These are analytical estimates, not real Android benchmark results. The hardware recommendation is therefore USB/10GbE tablets first, ordinary Wi-Fi phones later.

## Reproduce

```powershell
python -m unittest discover -s tests -p "test*.py" -v
python -m compileall -q scripts src tests
python scripts/simulate_comfyui_phone_ffn.py `
  --network-gbps 10 --phone-return gate_up_exact `
  --out results/comfyui_h3_phone_exact_10gbps.json
```

## Not Claimed Yet

- No end-to-end 27B-on-8GiB result.
- No real Android worker throughput result.
- No claim of universal speedup.
- No replacement of TeaCache, SageAttention, or ComfyUI's normal fallback path.
