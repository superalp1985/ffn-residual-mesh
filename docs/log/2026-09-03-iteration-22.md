# 2026-09-03 Iteration 22

## 目标

在连续 packet 布局上使用 `half2`，让一个 CUDA thread 同时处理两个 hidden 元素，减少重复读取 `coeff/index` 并提高 FFN residual merge 的计算密度。

## 先行调研

CUDA 提供 `__half2` 与 `__half22float2`，适合对齐的半精度二元读取和转换。本轮只改 GPU merge kernel，不改变 packet 字节布局、CPU 预展开公式或残差系数。

## 实现

`src/cuda_probe/ffn_artifact_probe.cu` 新增：

- `merge_packed_half2_kernel`：每线程处理两个连续 hidden 元素。
- `packed_half2_benchmarks`：与 scalar packed kernel 使用相同 H2D packet 和计时流程。
- 64-token packed half2 独立数值校验。

## 结果

数值校验全部通过：

- scalar packed vs fp16 reference：`mean rel-L2 = 0`，`max abs = 0`。
- half2 packed vs fp16 reference：`mean rel-L2 = 0`，`max abs = 0`。
- 近似输出 vs captured FFN：`mean rel-L2 = 2.2577%`。

同一可执行文件连续 5 次、每次 warmup 20 + measured 200，64-token 窗口中位数：

| 指标 | scalar packed | half2 packed | half2 相对变化 |
|---|---:|---:|---:|
| H2D ms | 0.04779 | 0.04853 | +1.5% |
| merge kernel ms | 0.04392 | 0.04316 | -1.7% |
| pipeline ms | 0.09116 | 0.09202 | +0.9% |

## 结论

1. `half2` 没有引入数值误差，但对该 residual merge 的收益太小，不能抵消 H2D 和 launch 抖动。
2. 当前优化重点应回到传输和调度：更大的连续 packet、slot 复用、减少 event/launch，而不是继续压缩已经很小的 merge kernel。
3. 负结果保留为后续决策依据：在 2048 hidden、top-k=4、64-token 窗口下，线程级二元向量化不是主要杠杆。
