## Research first

Rechecked CUDA stream/event overlap guidance before integration. The schedule must keep the CPU table evaluator independent of the copy/compute streams; only the final merge needs synchronization.

## Implementation

Added:

- `scripts/export_radix_table_artifact.py`
- `src/exact_main_residual_cuda_runner.cu`
- `scripts/build_and_run_main_residual_cuda.py`

The cold-start exporter materializes, for each of gate/up:

- exact base-4 partial-sum table;
- `high_sum`, alpha, beta and activation state files.

The runtime runner reads those artifacts only. It evaluates the radix main term on CPU and the exact 2-bit residual on GPU. CPU work is partitioned by output rows through a persistent thread pool. GPU work uses pinned packets and a two-slot copy/compute pipeline.

## Thread sweep

Results are medians from five repeats per process:

| CPU threads | CPU+GPU serial pair | CPU/GPU concurrent pair | speedup |
|---:|---:|---:|---:|
| 1 | 6.31 ms | 4.78 ms | 1.32x |
| 2 | 4.54 ms | 2.99 ms | 1.52x |
| 4 | 3.66 ms | 2.46 ms | 1.49x |
| 8 | 3.54 ms | 2.31 ms | 1.53x |
| 12 | 3.65 ms | 2.32 ms | 1.58x |
| 16 | 3.43 ms | 2.45 ms | 1.40x |

The CPU radix evaluator itself falls from roughly 2 ms/projection at one thread to roughly 0.64–0.70 ms/projection at 4–12 threads. Beyond that, results fluctuate and do not improve consistently, indicating a memory-bandwidth/scheduling knee rather than unlimited scaling.

## Decision

Continue. The pair schedule demonstrates the intended exchange: CPU performs the pre-expanded main-term work while GPU receives only the residual packet. At 8–12 threads, concurrent wall time is about 2.31–2.32 ms versus 3.54–3.65 ms for the same measured components in serial, a repeatable 1.5x-class reduction.

This is still a layer-level proof, not model-level throughput. The next required checks are exact `base + residual` output validation in the integrated runner, a persistent CPU pool across tokens, and a merged gate/up/SwiGLU/down path before claiming end-to-end benefit.
