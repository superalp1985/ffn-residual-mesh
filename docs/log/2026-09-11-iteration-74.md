# Iteration 74: Q5 Scheduling and Full Resident FFN

Date: 2026-09-11

## Objective

Remove the Q5/mixed-format launch shape that was silently over-provisioning
the grouped base kernel, then measure the complete resident path for two real
Qwen3.8-27B-class FFN layers:

```text
resident gate/up base + residual -> SwiGLU -> resident down projection
```

The measurement target is stable-state GPU utilization and transfer pressure,
not cold-start compilation time.

## Root cause

The old default launch shape was shared with the Q4 path:

```text
block_rows=2, num_warps=2, base_block_groups=256
```

For Q5 grouped decoding this creates a much larger register/resource footprint.
The kernel can remain numerically correct while being occupancy-limited or
effectively serialized. This was a scheduling failure, not an algebraic
failure and not evidence that the residual split cannot work.

The automatic Q5/mixed resolver now changes that legacy request to:

```text
block_rows=4, num_warps=2, base_block_groups=16
```

Q4 keeps its existing default. Sweep scripts disable automatic resolution so
candidate configurations are measured as requested.

## Full single-layer measurements

Command shape:

```text
benchmark_resident_tiled_ffn.py
  --warmup 8 --repeats 7
  --block-rows 2 --num-warps 2 --base-block-groups 256
```

The report records both the requested and resolved launch shape. The artifact
and down projection stay resident on the GPU during the repeated measurements.

| Layer | Gate/up format | Resolved base shape | Fused gate/up + SwiGLU | Down | Critical GPU path | Host wall |
|---:|---|---|---:|---:|---:|---:|
| 24 | Q5_K + Q4_K | 4 / 2 / 16 | 0.791 ms | 0.445 ms | 1.236 ms | 1.334 ms |
| 25 | Q5_K + Q5_K | 4 / 2 / 16 | 0.726 ms | 0.403 ms | 1.130 ms | 1.495 ms |

Values are medians over seven post-warmup samples on an RTX 4070 Laptop GPU
with PyTorch 2.9.1 + CUDA 13.0. Individual samples show occasional host or
down-kernel outliers; the medians above are the stable central measurements.

## Correctness and transfer accounting

| Layer | Resident payload | VRAM peak | Dynamic H2D | Activation D2D | Relative L2 | Max abs |
|---:|---:|---:|---:|---:|---:|---:|
| 24 | 206,110,720 B | 207,758,336 B | 0 B | 0 B | 2.72e-7 | 8.51e-7 |
| 25 | 217,251,840 B | 219,816,960 B | 0 B | 0 B | 2.51e-7 | 2.19e-6 |

The reference is a dequantized GGUF projection evaluated in float64 for the
synthetic one-token input. The resident path reconstructs the gate/up values
before SwiGLU and then applies the down projection. The measured error is
consistent with the expected floating-point/kernel accumulation differences;
the test is not an approximate lookup-table result.

The zero H2D/D2D values are a stable-state property: the resident package and
down payload are uploaded before the repeated token measurements. They do not
include cold-start artifact generation, initial upload, attention, KV cache,
layer paging, or host model orchestration.

## Interpretation

This iteration proves three narrower points:

1. A bad Q5 launch shape can dominate the measured time even when the
   reconstruction remains correct.
2. After resolving that shape, a complete resident FFN layer (gate/up,
   SwiGLU, and down) can execute on the 4070-class GPU in roughly 1.1–1.25 ms
   critical device time for a synthetic one-token input, with no per-token
   weight or activation copies in this path.
3. The remaining system problem is orchestration and coverage, not the
   existence of an exact split/merge kernel.

This is not a claim of 20 tokens/s for the complete 27B model. Attention,
KV-cache traffic, all-layer residency/windowing, CPU scheduling, real decode
sequences, synchronization policy, and end-to-end generation throughput are
still unmeasured. The next useful benchmark is a full decode loop with the
same instrumentation, not another isolated FLOPs comparison.
