# Iteration 76: GPU vs CPU Post-Residual Merge

Date: 2026-09-11

## Objective

Measure where the completed gate/up merge should run after the residual
product has been produced. The comparison includes the complete critical
path, not only the elementwise add:

```text
GPU path:       base + residual on GPU -> SwiGLU -> down
CPU path:       residual D2H -> CPU add -> merged gate/up H2D -> SwiGLU -> down
```

The objective is to minimize memory/VRAM traffic and keep the GPU fed. CPU
merge is not credited unless its required device transfers are included.


The CPU route uses pinned host buffers. Per layer it transfers two FP32
vectors in each direction:

```text
residual D2H:  2 * 17408 * 4 = 139,264 bytes
merged H2D:    2 * 17408 * 4 = 139,264 bytes
```

The GPU route keeps base and residual on CUDA and performs the merge in place
without a transfer.

## Results

Median timings:

| Layer | GPU critical path | CPU critical path | GPU speedup | GPU merge | CPU add | D2H + H2D |
|---:|---:|---:|---:|---:|---:|---:|
| 24 | 5.557 ms | 6.076 ms | 1.09x | 0.092 ms | 0.042 ms | 0.135 ms |
| 25 | 0.462 ms | 0.573 ms | 1.24x | 0.041 ms | 0.026 ms | 0.050 ms |

Both paths produced identical measured outputs:

```text
gate/up/SwiGLU/down relative L2 error: 0
GPU merge transfers: 0 B
CPU route transfers: 139,264 B D2H + 139,264 B H2D per layer
```

## Conclusion

For this resident FFN design, the merge belongs on the GPU. CPU elementwise
addition is cheaper in isolation, but the required D2H/H2D round trip makes
the complete path slower. The advantage is modest on layer 24 because its
SwiGLU/down work dominates; it is clearer on layer 25.

The governing rule remains:

```text
Do not move completed residual vectors to the CPU merely to perform a cheap
add. Keep the merge beside the next GPU consumer unless the CPU result can be
consumed without a return transfer.
```

This is a post-residual merge-placement result, not an end-to-end 27B
generation throughput claim. It does not measure attention, KV cache,
layer-window scheduling, or token-loop orchestration.
