# Iteration 56: Persistent Tile Steady State

Date: 2026-09-05

## Persistent Tile Mode

`TiledResidentGateUp` now supports a cold-start mode that uploads every
gate/up residual tile once and keeps the complete layer package in VRAM. This
is intentionally memory-first: cold-start cost is accepted to remove repeated
steady-state weight transfers.

For Qwen3.8-27B layer 3 (`111,411,200` bytes gate/up residual package):

| tile rows | cold wall | warm wall | warm tile kernel | weight H2D after cold start |
|---:|---:|---:|---:|---:|
| 512 | 192.0 ms | 6.1 ms | 3.49 ms | 0 additional bytes |
| 1024 | 12.0 ms | 6.9 ms | 4.03 ms | 0 additional bytes |
| 2048 | 19.9 ms | 2.7 ms | 1.12 ms | 0 additional bytes |

The first run includes Triton compilation and package initialization effects.
The warm path measures gate/up residual tiles, CPU base coefficients, and
SwiGLU. Down projection, attention, KV cache, and generation remain outside
this measurement.

## Interpretation

This validates the intended trade:

- spend cold-start time and VRAM to keep a layer's residual tiles resident;
- keep static base coefficients in system memory;
- avoid repeated residual weight H2D during steady-state execution.

The next bottleneck is no longer residual weight movement for a resident layer;
it is integrating down projection and then deciding which layers can remain
persistent under the 8 GB VRAM budget.
