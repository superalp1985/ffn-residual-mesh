# Iteration 50: 4-bit residual residency budget for Qwen3.8-27B

Date: 2026-09-05

## Assumptions

Verified Qwen3.8-27B-class FFN dimensions used by the project:

```text
hidden = 5120
intermediate = 17408
layers = 64
group = 32
```

The budget uses 4-bit residual codes (`0.5 bytes/weight`) plus one fp32 alpha
per 32-value input group. RTX 4070 Laptop reports 8188 MiB VRAM. The local
machine has 32 GiB system RAM.

## Static residency

```text
gate + up residual, one layer       106.25 MiB
gate + up residual, all 64 layers     6.64 GiB
gate + up + down residual, all layers 9.96 GiB
down Q4_K, all layers                 2.99 GiB
down Q4_K, one layer                 47.81 MiB
```

The gate/up all-layer package is theoretically close to the bare 8 GiB limit,
but leaves too little space for CUDA allocator state, attention/KV workspace,
ComfyUI, activations, and temporary buffers. It is not a robust resident plan.
All three residual projections do not fit.

## Dynamic buffers

For one layer, gate/up residual outputs are only 68 KiB in fp16 (136 KiB in
fp32). The int8 activation descriptor is about 5 KiB plus scales. These fit
easily; they are not the memory bottleneck.

## Paging consequence

If a 4-layer or 8-layer residual window is resident, batch-1 decode still visits
all 64 layers every token. The residual window must therefore be paged repeatedly
unless all layers remain resident. At effective PCIe 12 GB/s, paging the current
106.25 MiB gate/up package costs about 9.29 ms/layer, or about 595 ms/token for
64 layers before compute and attention. A window saves peak VRAM, but does not
remove the bandwidth bottleneck for decode.

## Decision

4-bit residuals can make a functional layer/window prototype run with host RAM
holding the full model, but they do not by themselves make an 8 GiB card a
bandwidth-free 27B runtime. To remove per-token paging, either:

1. reduce the all-layer resident residual package substantially and keep the
   required down representation resident too; or
2. compile a smaller structured residual and retain only that in VRAM, with
   explicit fallback for layers that do not meet the budget.

The current 4-bit all-layer residual proposal is therefore **functional with
window paging, not a 20-token/s guarantee and not a robust all-layer resident
design**.

## Architecture decision

Runtime radix-table lookup is now demoted from prerequisite to optional
evaluator. The main path is:

```text
offline split -> memory-map static base/residual artifact
             -> upload residual layer/window to VRAM once
             -> CPU/RAM computes base
             -> CUDA computes dynamic residual dots from VRAM
             -> merge gate/up before SwiGLU
             -> down projection
```

This avoids both runtime full-weight streaming and runtime radix-table
compilation. The download list and implementation plan are recorded in
`docs/asset_manifest.md` and
`docs/superpowers/plans/2026-09-05-resident-residual-qwen38-plan.md`.
