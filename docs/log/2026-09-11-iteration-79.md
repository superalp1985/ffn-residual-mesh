# Iteration 79: Q5 Group-Tile Sweep

Date: 2026-09-11

## Objective

Check whether the remaining resident Q5 gate/up latency is primarily caused by
the grouped decoder's `BLOCK_GROUPS` choice. The comparison keeps the same
artifact, input, CUDA Graph protocol, and exact split representation.

## Finding

`r4/w2/g16` is the fastest tested split shape on both layers and is close to
the direct packed path. A smaller group tile increases loop iterations
inside the same kernel; it does not increase the number of CUDA launches
here. Larger group tiles raise register use, and `g64` spills on both layers.
Changing to `r8/w4/g8` is also slower in these batch-1 comparisons.

This supports retaining the existing `r4/w2/g16` automatic schedule; it does
not establish a universal optimum. The resident comparison has no
per-invocation weight H2D transfer. It cannot identify missing DMA overlap in
a paged, nonresident full-model path. Attribution between instruction
throughput, device-memory bandwidth, occupancy and scheduling still requires
hardware counters or a controlled trace.

The layout and runtime weight bytes are unchanged: layer 25 uses
`217,251,840 B` versus `183,828,480 B` for the direct packed path, and layer
24 uses `206,110,720 B` versus `172,687,360 B`. There is no compression gain.
Absolute timings varied between runs, so compare configurations within each
paired run rather than treating cross-run differences as improvements.

The sweep does not establish an end-to-end model speed, a bandwidth reduction,
or a 20 tokens/s result. It only narrows the next optimization target:
activation/decode load organization and auxiliary coefficient traffic inside
the grouped gate/up kernel. No runtime defaults or kernel code changed in
this iteration.
