# 2026-09-02 Iteration 5

## 研究前置

再次核对了 LUT/向量量化和近似推理的工程路径。共识是：离线表和布局重排可以放在主机内存，运行时需要置信度门控与精确回退；不能把完整输出表按 token 搬到 GPU。

## 带宽交换模型

新增 `scripts/estimate_bandwidth_tradeoff.py`。以 Qwen3.5 每层 FFN 实测 20.25--23.34 MiB、`ffn_swiglu` 256 维分块、每块 K=8、rank=128 为例：

- 每层表和中心约 0.84 MiB，24 层约 20 MiB，适合冷启动时生成并放在 RAM。
- 若 GPU 常驻 rank-128 基底，每层约 0.5 MiB，一次性上传；运行时只传 256 B 系数。
- 若近似 token 占 75%、回退占 25%，按“系数路径”估算，每层 H2D 约为 `0.75*256 B + 0.25*FFN_weight`，相对每 token 传完整 FFN 权重可减少约 75%。
- 若 GPU 不常驻基底、改传完整 2048 维近似输出，则每个近似 token 约 4 KiB，仍比搬运 20--23 MiB 权重小得多。

这些是带宽下界，不含 kernel launch、CPU 分类、同步、PCIe 固定开销和误差传播；必须用端到端原型验证。

## 结论

“冷启动时间换显存/带宽”在数量级上成立，但收益取决于回退率：回退率高时会被精确权重搬运吞掉。第一版运行时应：

1. 冷启动生成表、中心、共享基底和每层阈值。
2. GPU 常驻少量基底；CPU 只分类并生成系数。
3. 连续 token 批量合并系数传输，低距离 token 走近似。
4. 超过阈值立即精确回退，不让错误跨层累积。
