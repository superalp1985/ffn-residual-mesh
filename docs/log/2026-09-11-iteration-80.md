# Iteration 80: Contiguous Activation Load Candidate

Date: 2026-09-11

## Objective

Test whether the Q5/mixed grouped gate/up kernel benefits from loading each
32-value activation group as one contiguous vector, then splitting it into
the even and odd channels used by the packed residual bytes.

The previous path loaded the two interleaved channel vectors separately:

```text
x[group*32 + 0, 2, 4, ...]
x[group*32 + 1, 3, 5, ...]
```

The candidate instead loads:

```text
x[group*32 + 0..31]
```

and uses Triton's `reshape` plus `split` primitives to recover the same two
16-value vectors. The candidate is opt-in and does not alter the default path.

## Implementation

Added:

```text
launch_fused_gate_up_base_residual(..., contiguous_x=False)
--compare-contiguous-x
```

The candidate is available only in the grouped Q5/mixed kernel. The diagnostic
rejects both grouped-kernel comparisons for pure Q4/Q4 artifacts because the
pure-Q4 kernel is a separate implementation and does not consume the flag.

Triton's official `split` documentation was retrieved on 2026-09-11 and
confirms that it splits a tensor along a final dimension of size two; this is
the primitive used after reshaping `(BLOCK_GROUPS, 16, 2)`.

```text
https://triton-lang.org/main/python-api/generated/triton.language.split.html
```

## Correctness

The focused CUDA tests cover:

- Q5/Q5, Q5/Q4 and Q4/Q5 residuals;
- grouped launch configurations `r4/w2/g16` and `r8/w4/g8`;
- tail rows and tail groups;
- `contiguous_x` alone and combined with `scale_after_reduce`;
- independent FP64 numerical references.

All candidate outputs remained within the existing `5e-5` focused-test
tolerance and the diagnostic's `1e-4` reference threshold.

| Variant | Median device span | P95 | Gate/up + SwiGLU | Registers/thread | Spills |

| Contiguous activation load | `1.194 ms` | `1.309 ms` | `0.673 ms` | 127 | 0 |

Both variants passed the independent GGUF FP64 reference check with maximum
relative L2 `2.56e-7`. The candidate won 52 of 101 paired rounds. Its
instrumented gate/up stage was about `0.003 ms` lower, but the complete FFN
span was about `0.75%` higher; this is not a stable improvement.

Full-span timing and stage timing came from separate passes. The stage pass
adds CUDA event nodes and its gate/up interval includes the group-sum
reduction. Do not subtract its stage median from the uninstrumented full-span
median to infer a kernel gap. No hardware-counter trace was collected.
The error is additional to the existing GGUF quantization, not an estimate
of error relative to the original full-precision model.

## Finding

Contiguous activation loading is mathematically correct and slightly reduces
the compiled register count, but it does not improve complete-layer latency
under the paired protocol. Keep it as an opt-in research switch and leave the
default `contiguous_x=False`.

This measurement supplies no reason to promote the loading change. It does
not prove the original load was inefficient, or identify which instructions
dominate the remaining latency. The grouped Q5 decoder still contains residual
unpacking, per-group scale/coefficient loads, reductions and SwiGLU dependency
work. Runtime weights remain `217,251,840 B` for both split variants versus
`183,828,480 B` for the direct packed-Q5 implementation. No bandwidth
reduction, compression gain, or end-to-end 20 tokens/s result is established.
