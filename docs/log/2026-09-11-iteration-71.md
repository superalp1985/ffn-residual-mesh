# Iteration 71: Four-Layer Resident Device Chain

Date: 2026-09-11

## Objective

Extend the resident FFN device chain from two layers to four consecutive
Qwen3.8-27B layers. The purpose is to test whether host submission overhead or
hidden activation copies grow into the dominant cost as the chain gets longer.

## Research and protocol

CUDA stream ordering, event timing, and graph/stream dependency guidance were
checked before this iteration. The new runner submits all layers to one
explicit CUDA stream and synchronizes only at the tail for the main chain
measurement. CUDA event markers are placed after each layer to expose the
per-layer interval.

This is still a synthetic one-token device-chain benchmark. It does not
measure SM occupancy, DMA-engine utilization, attention, KV cache, paging, or
end-to-end generation throughput.

Configuration:

- GPU: NVIDIA GeForce RTX 4070 Laptop GPU, 8 GiB
- PyTorch: 2.9.1+cu130
- CUDA runtime: 13.0
- layers: 3 -> 21 -> 40 -> 42
- gate/up: resident Q4_K, GPU base, fused residual + SwiGLU
- down: native GGUF quantized projections
  - layer 3: IQ4_NL, rows=2, warps=2, qblocks=4
  - layer 21: Q4_K, rows=2, warps=2, qblocks=4
  - layer 40: Q5_K, rows=2, warps=2, qblocks=4
  - layer 42: IQ4_XS, rows=4, warps=2, qblocks=4

## Result

From `results/resident_device_chain_3_21_40_42_iter71.json`:

| Mode | Median GPU span | Median host wall/enqueue |
|---|---:|---:|
| host-sync chain | 5.804 ms | 5.844 ms |
| tail-sync chain | 5.044 ms | 5.091 ms |
| explicit async submission | 5.382 ms | CPU enqueue 0.639 ms |

Per-layer CUDA marker intervals in the tail-sync chain:

| Layer | Interval |
|---:|---:|
| 3 | 1.258 ms |
| 21 | 1.139 ms |
| 40 | 1.149 ms |
| 42 | 1.254 ms |

All four layers report:

- activation H2D: `0 B`
- activation D2D: `0 B`
- base-result H2D: `0 B`
- resident-weight H2D: `0 B`

## Interpretation

The four-layer chain remains close to the sum of its actual layer intervals.
The CPU enqueue median is substantially below the device span, and no runtime
weight or activation copies are introduced by chaining. This supports the
current conclusion that the measured path is dominated by the quantized FFN
kernels, not by a large host-side submission gap.

The measurement does not prove that different layers overlap concurrently;
they are dependent because each layer consumes the previous layer's output.
The next hardware-level check should use Nsight Systems/Compute or CUPTI
counters, if available, to distinguish kernel execution, memory stalls, and
DMA activity.
