# 2026-09-04 Iteration 38: Radix Table Size Trade-off

## Research first

Rechecked CUDA memory-transfer guidance for page-locked host allocations and asynchronous staged transfers. The test keeps the transport path unchanged and varies only the CPU main-term table geometry.

## Experiment

Compared exact radix block sizes with the same layer-23 QLO2 residual artifact, 1024-row GPU tiles, 8 CPU pool threads and 5 repeats:

| block size | table per projection | cold-start behavior | serial pair | concurrent pair | speedup |
|---:|---:|---|---:|---:|---:|
| 4 | 768 MiB | faster compile, larger RAM | 3.48 ms | 2.40 ms | 1.45x |
| 2 | 96 MiB | much lower RAM, slower compile | 4.38 ms | 3.21 ms | 1.36x |

The residual packet is unchanged. The lower-memory block-2 table remains viable and preserves a measurable CPU/GPU overlap benefit, but its extra CPU lookups reduce the layer-level result by about 6% relative to block 4 in this run.

## Decision

Keep both formats in the compiler:

- block 4 is the performance candidate when host RAM is available;
- block 2 is the constrained-RAM fallback;
- no need to force a single global table geometry.

The next engineering gate is numerical validation of the integrated `base + residual` output and then a gate/up SwiGLU merge. Down projection remains outside this layer transport proof until the merge path is validated.

## Persisted-artifact verification

Both block-2 and block-4 artifacts were read back from disk and compared with the original Q4_K codes in an offline verifier:

- `integer_high_exact = true` for gate and up;
- `base_max_abs = 0`;
- `merged_max_abs = 4.768e-7`;
- merged relative L2 was `9.05e-8` (gate) and `1.01e-7` (up).

This closes the artifact serialization gap: the table and residual files preserve the same exact integer-domain split as the in-memory compiler.
