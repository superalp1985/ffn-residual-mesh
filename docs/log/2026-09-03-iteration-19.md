# 2026-09-03 Iteration 19

## 目标

继续验证真实 CUDA 链路中的两个系统变量：

1. 精确回退权重在窗口内驻留复用，是否能避免逐 token 重传。
2. pinned ring buffer 使用 copy stream / compute stream 和 event 依赖后，分块搬运和 residual merge 能否流水化。

## 本轮调研

- CUDA 的异步 H2D 与计算重叠要求 host memory 可页锁定，并使用不同的 non-blocking stream。
- `cudaEventRecord` + `cudaStreamWaitEvent` 可建立跨 stream 的生产者/消费者依赖，而不需要设备级全同步。
- ggml 对应提供 `ggml_backend_tensor_copy_async`、backend event record/wait，后续可把相同结构映射到 backend。

## 新增模式

`exact_fallback_reuse`：

```text
H2D(full down weight) once per token window
then reuse the resident page for all fallback tokens in that window
```

`base_plus_residual_overlap`：

```text
copy_stream: H2D(chunk_i) -> record ready_i
compute_stream: wait ready_i -> merge(chunk_i) -> record done_i
copy_stream: wait done_(i-ring_slots) before reusing a slot
```

同时修正了 GPU merge，使常驻 `mu_r` 真正进入公式：

```text
y_hat = base + mu_r + sum_i alpha_i U_i
```

GPU/CPU 数值校验仍为：

```text
max_abs_error=0
mean_abs_error=0
```

绝对时延会受 GPU 当前负载影响；本轮应主要比较同次运行内的数量级和模式差异。

## 结论

1. 回退权重页缓存不是小优化，而是成败条件。窗口内只搬一次时，64-token 压力代理从约 60--65 ms 降到约 1.5--1.8 ms。
2. 即使只搬一次完整 down 权重，约 10 MiB/window 仍明显高于近似包约 0.3 MiB/window；因此回退率和跨窗口常驻命中率必须进入最终 policy。
3. 当前 overlap 模式比整窗一次 H2D 更慢，原因是它按 16-token 子块提交三次小 copy、多个 event 和 kernel，且每个子块单独按超级块计费。它验证了 ring/event 依赖正确，但没有证明重叠收益。
4. 对这么小的 residual merge，流水化粒度不能只看 token 数；应让每个提交块达到足够的字节量，并把 base/coeff/index 预打包成真正连续的 pinned slot，避免三次小 copy。
5. `mu_r` 必须常驻 GPU，否则此前的系统原型只验证了 `base + U alpha`，与完整离线公式不一致。本轮已修正并重新通过数值校验。
