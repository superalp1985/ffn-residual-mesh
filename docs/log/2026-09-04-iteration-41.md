# 2026-09-04 Iteration 41: CPU Base + GPU Full FFN Tile Runner

## Research first

Rechecked the CUDA staged-pipeline requirements before integrating the full chain: every H2D operation must execute on the copy stream, its ready event must be recorded on that same stream, and the compute stream must wait on that event. Timing also needs separate per-tile copy-active, compute-active, and end-to-end critical-path events.

## Experiment

The new `scripts/benchmark_cpu_base_gpu_full_ffn.py` runner uses the persisted radix base as a CPU-preexpanded result, packs exact QLO2 residual plus alpha into pinned H2D packets, and processes six 1024-row tiles. Each tile executes:

```text
H2D residual + small base result -> exact residual reduction -> base + residual -> SwiGLU -> down partial
```

The resident down projection is fp16 dequantized Q4_K (`24 MiB` on GPU). Only the residual packets and the small CPU base vectors cross H2D during the run.

## Results

Layer 23, block-2 table, 1024-row tiles, 10 repeats:

- residual H2D: `9.0 MiB` per gate+up pair;
- CPU base auxiliary data: `49,152 bytes` total, `8,192 bytes` per tile;
- serial critical path: `1.80 ms` median;
- double-buffer critical path: `1.22 ms` median;
- critical-path improvement: `1.47x`;
- copy-active time: about `0.82 ms` serial and `0.86 ms` overlapped;
- compute-active time: about `0.41 ms` serial and `0.46 ms` overlapped.

The absolute numbers vary with scheduling, so the critical path and active-event measurements are both retained. The important result is that copy and compute are now a real multi-tile dependency chain rather than two isolated benchmarks.

## Correctness

- all six tile SwiGLU relative L2 errors: `1.0e-7` to `2.1e-7`;
- all six tile down-partial relative L2 errors: `1.6e-4` to `1.9e-4`;
- full down output relative L2 against fp32 CPU accumulation: `1.18e-4`.

Two implementation races were fixed during this round:

1. H2D copies were accidentally issued on the default stream instead of the copy stream, allowing compute to read incomplete packets.
2. The down kernel omitted the tile's global column offset and reused the first 1024 down columns for every later tile.

## Decision

The first complete CPU-preexpanded-base + GPU-residual/SwiGLU/down tile runner is numerically valid and shows measurable double-buffer critical-path reduction. It is still a single-token bridge, not a full model-speed claim. The next experiment should sweep tile size and then connect the CPU table evaluator itself to the same stream schedule so CPU base production and GPU residual work overlap in one measured loop.
