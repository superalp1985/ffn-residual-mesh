# Iteration 75: CUDA Graph Capture for a Resident FFN Chain

Date: 2026-09-11

## Objective

The previous same-stream chain already removed runtime weight and activation
copies, but each layer still submitted several dependent operations from Python.
This iteration captures the complete two-layer resident dependency chain:

```text
layer 24 gate/up + SwiGLU + down
    -> layer 25 gate/up + SwiGLU + down
```

The graph uses fixed GPU addresses and replays one resident activation. It is
intended to measure launch-gap reduction, not to represent a full decode loop.

## Measurement

Artifact and model:

```text
data/resident_qwen38_layer24_exact_v2
data/resident_qwen38_layer25_exact_v2
E:\Qwen3.8-27B\Qwen3.8-27B-UD-Q4_K_M.gguf
```

Hardware/software:

```text
RTX 4070 Laptop GPU, PyTorch 2.9.1+cu130, CUDA 13.0
warmup=8, repeats=7
```

| Path | GPU time | CPU submission |
|---|---:|---:|
| normal same-stream async chain | 2.271 ms | 0.348 ms |
| whole-chain CUDA Graph replay | 2.097 ms | 0.071 ms |

The graph capture itself took 4.39 ms after warmup. Replay samples ranged from
2.08 to 2.66 ms; the median is reported above.

All measured transfer counters remain zero:

```text
activation H2D = 0 B/layer
activation D2D = 0 B/layer
base H2D       = 0 B/layer
resident H2D   = 0 B/layer
```

## Interpretation

Capturing the whole dependent chain reduces host enqueue overhead by about 80%
and reduces the measured device interval by about 0.17 ms (roughly 8% in this
two-layer sample). The gain is real but bounded: the graph cannot remove the
actual gate/up, SwiGLU, and down arithmetic. It mainly removes repeated Python
submission and event/launch scheduling overhead.

This also confirms that the zero-copy resident path is compatible with a
fixed-address graph. The input activation is allocated on the GPU before
replay; this benchmark deliberately does not include an H2D update per replay.

## Limits

This is not a 27B end-to-end generation result. The benchmark still excludes
attention, KV cache, all-layer windowing, token-by-token input updates, CPU
model orchestration, and real sampling. A production graph would need either
stable input/output buffers with a small device-side update or a graph-per-shape
policy. The next system-level test should measure a real decode loop while
retaining the same transfer ledger.
