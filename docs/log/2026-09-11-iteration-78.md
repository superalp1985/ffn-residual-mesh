# Iteration 78: Scale After Group Reduction

Date: 2026-09-11

## Objective

Reduce arithmetic and register pressure in the mixed Q4/Q5 resident gate/up
kernel without changing the split representation, runtime weight bytes, or
the exact mathematical decomposition.

For each 32-value group, the residual term is:

```text
alpha_g * sum_i(residual_gi * x_gi)
```

The candidate computes the group dot product first and multiplies by
`alpha_g` afterward. Since `alpha_g` is constant within the group, this is
algebraically equivalent. Floating-point reduction order remains a possible
source of tiny round-off differences and is measured independently.

## Implementation

Added an optional `scale_after_reduce` flag to the mixed Q4/Q5 fused resident
kernel. The default remains unchanged. The diagnostic can compare both forms
in the same randomized CUDA Graph protocol:

```text
--compare-scale-reduction
```

The test suite now covers Q5/Q5, Q5/Q4, and Q4/Q5 packed residuals, tail rows,
independent FP64 reference output, and kernel resource reporting.

## Results

Real Qwen3.8-27B layer 25, Q5_K gate/up/down, RTX 4070 Laptop GPU, CUDA 13.0:

```text
artifact: data/resident_qwen38_layer25_exact_v2
warmup: 2 s
repeats: 15
inner: 4
configuration: block_rows=4, num_warps=2, block_groups=16
```

| Variant | Median device span | Max reference relative L2 | Registers/thread |
|---|---:|---:|---:|
| Existing order | 1.222 ms | 2.44e-7 | 128 |
| Scale after group reduction | 1.144 ms | 2.46e-7 | 127 |

The separate instrumented stage pass measured the gate/up plus SwiGLU stage at
`0.679 ms` for the existing order and `0.662 ms` for the candidate. Down was
unchanged at about `0.40 ms`. The uninstrumented result is encouraging but
not conclusive: samples contain visible timing variability. No synchronized
clock or hardware-counter trace was collected to establish its cause.

The candidate has no spill according to Triton resource metadata. Runtime
weight bytes are identical at `217,251,840 B`; this is a compute/register
ordering experiment, not a compression or bandwidth reduction.

Longer paired runs do not establish a stable speedup:

| Layer / gate+up | Existing median | Candidate median | Candidate delta |
|---|---:|---:|---:|
| 25 / Q5+Q5 | `1.180 ms` | `1.175 ms` | `-0.4%` |
| 24 / Q5+Q4 | `1.282 ms` | `1.271 ms` | `-0.9%` |

Each run used 5 seconds of warmup, 101 randomized paired rounds, and
`inner=16`; both runs validated against the independent reference. The
layer-25 candidate won 56/101 paired rounds and layer 24 won 59/101, so the
small median differences do not establish a repeatable kernel benefit over
the observed timing variability.

Long-run artifacts:

```text
artifacts/l25_scale_after_reduce_long_seed7802.json
artifacts/l24_scale_after_reduce_long_seed7803.json
```

The candidate maximum relative L2 against the independent reference was
`2.53e-7` on layer 25 and `2.63e-7` on layer 24. The respective existing-order
values were `2.54e-7` and `2.70e-7`. These are differences relative to the
quantized GGUF model, not a measure of that model's quantization error against
the original full-precision model.

## Finding

The candidate is algebraically equivalent, with measured floating-point
round-off. The short-run latency improvement did not hold at the same
magnitude in the longer cross-layer runs. Q5/Q5 uses one fewer register per
thread; Q5/Q4 remains at 128 for both variants. This is a weak directional
signal, not a stable speedup. It should remain opt-in. The diagnostic now rejects
`compare_scale_reduction` for pure Q4/Q4 gate-up artifacts because the
existing pure-Q4 kernel does not implement this variant. The main bottleneck
is still the gate/up decode and residual dot path; the Q5 down projection is
not affected.

No default behavior was changed in this iteration.

## Research boundary

The optimization follows the standard invariant that a GEMV-like FFN path is
memory and decode sensitive rather than compute-FLOP limited. It does not
claim that reassociation alone solves DRAM bandwidth, DMA scheduling, or
cross-layer pipeline bubbles. Those require separate measurements.

Layer 25 still uses `217,251,840 B` of runtime weights versus `183,828,480 B`
for the original packed Q5 projections: an 18.18% increase, not compression.
