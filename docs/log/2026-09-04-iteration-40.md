# 2026-09-04 Iteration 40: GPU Compute-Density Bridge

## Research first

Rechecked the staged CUDA transfer model and the Triton pointer/stride contract before rerunning the bridge. The transport remains a pinned host packet followed by a dependent GPU residual kernel; this round changes only pointer correctness, cold-start loading, and end-to-end validation.

## Fixes

1. The packed code and alpha values remain in one H2D packet, but the Triton kernel now receives the full packet row stride and the alpha byte offset explicitly. The previous sliced float view retained a stride of the full packet row, while the kernel incorrectly assumed a compact `[rows, groups]` view; rows after the first could read out of bounds and produce `Inf/NaN`.
2. Cold-start loading now dequantizes only the resident `down` projection. The bridge does not need to dequantize gate/up because those projections already come from the radix table and QLO2 artifact.
3. The benchmark now validates the complete chain: `base + residual`, `SwiGLU`, and resident fp16 `down` projection output.

## Experiment

Layer 23, Qwen3.5 dimensions `hidden=2048`, `ffn=6144`, one token, exact 2-bit residual, 20 repeats for block-2 and 10 repeats for block-4:

| radix table | residual H2D | residual-only compute | full compute (`SwiGLU + down`) | compute ratio |
|---|---:|---:|---:|---:|
| block 2 | 9.0 MiB | 0.257 ms | 0.364 ms | 1.41x |
| block 4 | 9.0 MiB | 2.529 ms | 3.584 ms | 1.42x |

The absolute timings vary with host/GPU scheduling, but both table geometries show the same qualitative result: keeping more GPU work after the residual transfer lengthens the dependent compute segment by about 40% without increasing the residual packet.

## Correctness

- gate residual relative L2: `1.73e-7`;
- up residual relative L2: `1.79e-7`;
- merged gate relative L2: `9.12e-8`;
- merged up relative L2: `1.00e-7`;
- SwiGLU relative L2: `1.68e-7`;
- fp16 down output relative L2: `2.91e-4`;
- both residual outputs finite.

The large merged error seen before this round was a validation bug: the CPU full-reference path accidentally used `beta=0`, omitting the Q4 zero-point term. It was not a GPU arithmetic error.

## Decision

This closes the narrow density-bridge gate: an exact residual packet can feed `base + residual -> SwiGLU -> resident down` with near-float32 agreement while adding useful GPU work per transferred byte. It is not an end-to-end model-speed claim and it does not yet measure stream overlap or hardware occupancy.

Next round: integrate the same chain into the CPU-main/GPU-residual double-buffer runner, then report copy/compute overlap, critical-path time, and GPU wait intervals.
