# Iteration 59: super-tile base/residual fusion

## Question

Can the residual feed be made dense enough that H2D, tile, and merge gaps stop
dominating the GPU critical path?

## Changes

- Added `base_on_gpu=True` to `TiledResidentGateUp`.
- Coefficient matrices are uploaded once and kept resident in fp32.
- Runtime base input is only the 160-element group-sum vector.
- Added a Triton full super-tile kernel:
  `residual dot + coefficient base + gate/up merge + SwiGLU`.
- Kept the tiled fallback for swapped layers and small test fixtures.
- Added CUDA-device synchronization before timing/down-output reads.

## Measured

Hardware: RTX 4070 Laptop, CUDA 13.0, Qwen3.8-27B Q4_K_M gate/up artifacts.

Warm single-token gate/up, full resident layer:

| Layer | CPU base path | GPU fused super-tile |
|---|---:|---:|
| 3 | ~1.51 ms | ~1.41 ms |
| 21 | ~1.89 ms | ~1.33 ms |

These are layer measurements, not end-to-end generation claims. The full fused
kernel preserves the split output within roughly `1e-6` absolute error on the
tested artifacts.

## Interpretation

The useful unit is no longer a page-sized residual fragment. For resident layers
it is a full FFN super-tile that keeps the matrix unit busy while reusing the
same activation and group sums. For evicted layers, coarse double-buffered tiles
remain necessary because their weight H2D is still on the critical path.

Next: fixed-shape CUDA Graph replay, Nsight Systems/Compute gap and pipe-active
measurement, then a real multi-layer runner.
