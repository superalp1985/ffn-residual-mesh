# Iteration 64: FP32 CPU Base 与提交空隙消除

日期：2026-09-06

## 本轮问题

第 63 轮的真实 layer 21 CPU-base 路径中，gate/up 主项使用 FP64 group
sum、FP64 coefficient 和一次临时结果复制到 pinned buffer。该路径的 CPU
中位数约 `0.861 ms`，超过或接近 resident residual kernel，因此会留下约
`0.400 ms` 的可见 GPU submission gap。

本轮目标是缩短这个主机侧关键路径。整数 code split、4-bit residual 和 GPU
residency 都不改变。

## 调研边界

CUDA 的 page-locked host memory 配合 `cudaMemcpyAsync`/non-blocking copy 能由
驱动调度异步传输；stream event 只表达数据依赖。它不能消除 CPU 尚未准备好
base vector 的等待，也不能消除 gate/up -> SwiGLU -> down 的数学依赖。

参考：

- NVIDIA CUDA C Best Practices Guide:
  https://docs.nvidia.com/cuda/cuda-c-best-practices-guide/index.html
- NVIDIA CUDA C Programming Guide, asynchronous execution:
  https://docs.nvidia.com/cuda/cuda-c-programming-guide/index.html

因此先用 CPU base 时间和同一 CUDA stream 的 event gap 判断是否存在可消除的
提交空隙；不将 CUDA event 误报为 SM occupancy 或 DMA-engine utilization。

## 实现

`scripts/compile_resident_residual_artifact.py`

- 新 artifact 的 `coefficient = alpha * base + beta` 以连续 `<f4` 写入；
- layer 21 gate/up static coefficient 从 `44.6 MiB` 降到 `22.3 MiB`。

`src/resident_residual_format.py`

- reader 从 manifest 读取 coefficient dtype；
- 接受新 `<f4` 与旧 `<f8` payload，其他 payload 类型仍拒绝。

`src/resident_residual_cuda.py`

- cold start 只做一次旧/新 coefficient -> 连续 FP32 转换；
- 预分配 FP32 `group_sums`；
- `np.sum(..., out=group_sums)` 与
  `np.matmul(coefficient, group_sums, out=pinned_base)` 直接写入 pinned base
  buffer，删除每 token 的 FP64 cast、临时 matmul result 和额外复制。

`scripts/benchmark_cpu_base_precision.py`

- 新增真 layer artifact 的 FP64/FP32 CPU base GEMV 与线程数扫描。

## CPU Base 扫描

真实 Qwen3.8-27B Q4_K layer 21，gate/up 合计：

```text
FP64 coefficient + FP64 sums: 0.226 ms best
FP32 coefficient + FP32 sums: 0.131 ms best
FP32 vs FP64 base relative L2:
  gate = 1.17e-7
  up   = 1.18e-7
```

这不是权重拆分误差：Q4_K 码值和 residual 未压缩、未裁剪。它只是在 CPU
base 的浮点累加顺序和存储精度上作资源取舍，最终完整 FFN 仍按原始 Q4_K
reference 测量。

## 真实 Layer 21 结果

环境：

```text
GPU: NVIDIA GeForce RTX 4070 Laptop GPU, 8 GiB
PyTorch: 2.9.1+cu130
CUDA: 13.0
模型: Qwen3.8-27B-UD-Q4_K_M.gguf
FFN: hidden=5120, ffn=17408
```

新 FP32 artifact、21 个 warm samples 的中位数：

```text
CPU base                       0.449 ms
resident gate/up residual      0.822 ms
Q4_K down + SwiGLU             0.735 ms
CUDA stream span               1.726 ms
exposed CPU submission gap     0.002 ms
wall                           2.052 ms
output relative L2             2.49e-7
dynamic H2D                    159,744 B/token
residual weight H2D warm run   0 B/token
```

旧 FP64 artifact 在新 runner 中只于冷启动转成 FP32，也通过完整 reference：

```text
CPU base                       0.398 ms
exposed CPU submission gap     0.001 ms
output relative L2             2.49e-7
```

两者的微小 wall 波动受短 kernel 调度和笔记本 GPU 时钟状态影响，不能把单次
wall 差异解释为 artifact dtype 的收益。可重复结论是：FP32 的原地 CPU
base 路径已经稳定藏在 gate/up residual span 内，之前约 `0.4 ms` 的主机提交
空隙不再是当前关键路径。

## 判断

1. 当前事件证据不支持“因为没有 DMA，所以单层严格串行”的归因。CPU-base
   的可见 gap 已降至约 `0.002 ms`；但没有 driver counter 权限时，仍不能声称
   DMA engine utilization。
2. 完整 layer 仍不是 `0.3~0.5 ms`，原因是 GPU 至少需完成 Q4_K gate/up
   residual dot 与 Q4_K down dot。当前约 `1.5 ms` 的 device-active kernels
   是 Q4_K decode、VRAM reads 和 batch=1 reduction 的主要成本。
3. 后续 GPU 优化应针对量化 GEMV layout、decode/dot fusion、register/shared
   memory staging 或 CUTLASS/cuBLASLt-friendly packing；继续压 CPU base
   不会带来主要收益。
4. 本结果仍是单层 synthetic activation 实验，不是全模型 tok/s，不包括
   attention、KV、layer window paging 或生成质量。
