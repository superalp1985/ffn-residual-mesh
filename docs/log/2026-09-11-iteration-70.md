# Iteration 70: Resident FFN and Mixed Down-Kernel Chain

Date: 2026-09-11

## Objective

Measure the complete resident FFN path on representative Qwen3.8-27B layers
after tuning the quantized down-projection kernels. The target is to reduce
runtime weight traffic and submission gaps, not to reduce the mathematical
operation count.

## Research and protocol

The CUDA stream/event and CUDA Graph execution model was checked before this
iteration. The measurements below use the existing resident device path and
CUDA events. They are device-work timings for synthetic inputs, not a model
generation benchmark. No claim is made about SM occupancy, DMA-engine
utilization, attention, KV cache, paging, or end-to-end token rate.

Configuration:

- GPU: NVIDIA GeForce RTX 4070 Laptop GPU, 8 GiB
- PyTorch: 2.9.1+cu130
- CUDA runtime: 13.0
- model: `E:\Qwen3.8-27B\Qwen3.8-27B-UD-Q4_K_M.gguf`
- gate/up: Q4_K exact resident split, `grouped_fused`, `block_rows=8`,
  `num_warps=4`, `block_groups=16`
- down: native quantized projection with per-layer tuned launch parameters

## Single-layer results

| Layer | Down format | Down config | CPU base | Residual | SwiGLU + down | Critical path | Relative L2 |
|---:|---|---|---:|---:|---:|---:|---:|
| 21 | Q4_K | rows=2, warps=2, qblocks=4 | 0.296 ms | 0.514 ms | 0.424 ms | 1.219 ms | 2.48e-7 |
| 40 | Q5_K | rows=2, warps=2, qblocks=4 | 0.335 ms | 0.499 ms | 0.421 ms | 1.166 ms | 2.56e-7 |
| 42 | IQ4_XS | rows=4, warps=2, qblocks=4 | 0.332 ms | 0.498 ms | 0.509 ms | 1.217 ms | 3.00e-7 |

Layer 42 previously used a less suitable launch shape. `block_rows=4` reduces
the measured down stage to about 0.51 ms in this run. It is an improvement to
the kernel schedule, not a change to the split or merge formula.

For all three layers:

- resident weight H2D during the measured token path: `0 B`
- dynamic activation/base H2D reported by the single-layer runner:
  `159,744 B/token`
- event-accounted exposed submission gap: about `0.001-0.002 ms`
- error is against the independent GGUF dequantization reference on synthetic
  inputs; it is not a task-quality evaluation

## Two-layer device chain

Measured chain: Layer 40 -> Layer 42.

| Mode | GPU span | Wall/enqueue observation |
|---|---:|---:|
| host-sync | 2.998 ms | host wall median 3.024 ms |
| tail-sync | 2.645 ms | one explicit stream, synchronize at tail |
| explicit async | 2.760 ms | CPU enqueue median 0.335 ms |

The chain reports zero activation, base-result, and resident-weight H2D bytes
per layer. The per-layer down launch settings are retained in
`results/resident_device_chain_layer40_42_iter70.json`:

- Layer 40: Q5_K, rows=2, warps=2, qblocks=4
- Layer 42: IQ4_XS, rows=4, warps=2, qblocks=4

This demonstrates that consecutive resident layers can be submitted on a
device stream without host-side tensor copies. It does not demonstrate
cross-layer kernel overlap or prove a full-model token rate.

## Decision

Keep the mixed down-kernel settings above as the current layer-specific
baseline. The complete FFN path is now dominated by the quantized residual and
down kernels rather than a measurable host submission gap in this benchmark.
The next useful measurement is a longer representative layer chain with
hardware counters or Nsight, if available, to distinguish true SM/DMA overlap
from merely contiguous same-stream execution. End-to-end generation remains
unmeasured.
