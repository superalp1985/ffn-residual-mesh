# 2026-09-04 Iteration 42: Tile-Size Sweep

## Research first

Rechecked the staged copy/compute event placement before comparing tile sizes. All timed H2D operations run on the copy stream, ready events are recorded after the copies, and compute-active time is the sum of per-tile kernel intervals rather than `critical - copy`.

## Experiment

Layer 23, block-2 radix artifact, exact QLO2 residual, CPU-preexpanded base vectors, resident fp16 down projection, five repeats per tile size:

| tile rows | tile count | serial critical | double-buffer critical | speedup | copy active (overlap) | compute active (overlap) |
|---:|---:|---:|---:|---:|---:|---:|
| 512 | 12 | 2.358 ms | 2.172 ms | 1.09x | 1.254 ms | 0.450 ms |
| 1024 | 6 | 1.379 ms | 1.018 ms | 1.36x | 0.834 ms | 0.410 ms |
| 2048 | 3 | 1.319 ms | 0.948 ms | 1.39x | 0.782 ms | 0.337 ms |
| 6144 | 1 | 1.111 ms | 1.135 ms | 0.98x | 0.779 ms | 0.281 ms |

The residual traffic is unchanged at `9.0 MiB` per gate/up pair. The CPU base result adds only `49,152 bytes` total, or `16,384 bytes` per 2048-row tile.

## Correctness

All four tile sizes preserve the same numerical boundary:

- full down output relative L2: about `1.18e-4`;
- per-tile SwiGLU relative L2: about `1e-7` to `2e-7`;
- per-tile down partial relative L2: about `1.2e-4` to `2.1e-4`.

## Decision

Use 2048 rows as the current RTX 4070 / layer-23 candidate because it has the lowest measured critical path and the best overlap ratio in the clean sweep. Keep 1024 as the finer-grained fallback when CPU production or scheduling needs more pipeline stages. Avoid 512 unless a later workload shows enough independent work to amortize its event/launch overhead; avoid 6144 when overlap is required.

This is still a preexpanded-base GPU bridge. The next step is to put the CPU radix evaluator itself in the measured loop and overlap its production with the same GPU tile schedule.
