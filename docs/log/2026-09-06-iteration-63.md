# Iteration 63: Q4_K K-tiled down 与固定图回放

日期：2026-09-06

## 本轮问题

复核“完整 FFN 单层仍高于 `0.3~0.5 ms` 是否主要因为 H2D 没有使用硬件
DMA、或层间被不必要地串行阻塞”。目标不是减少 FLOPs，而是减少稳态动态
传输、提交空隙和 GPU 等待。

## 调研边界

先复核 CUDA 官方语义：

- page-locked host buffer 配合 non-default copy stream 才能让异步 H2D 与
  compute overlap；本项目 CPU-base 路径使用 pinned staging buffer；
- stream event 只表达依赖，不能解除数学数据依赖；
- CUDA Graph 适合固定拓扑的重复提交，主要削减 CPU launch / driver
  submission 开销，不会消除 Q4_K 解码、显存读取或 GEMV 规约。

来源：

- NVIDIA CUDA C Best Practices Guide:
  https://docs.nvidia.com/cuda/cuda-c-best-practices-guide/index.html
- NVIDIA CUDA C Programming Guide, streams and asynchronous execution:
  https://docs.nvidia.com/cuda/cuda-c-programming-guide/index.html
- NVIDIA CUDA C Programming Guide, CUDA Graphs:
  https://docs.nvidia.com/cuda/cuda-c-programming-guide/index.html#cuda-graphs

## 实现

`src/resident_residual_cuda.py`

- Q4_K down 改为 K-tiled 单 Triton kernel；
- 累加器保留在寄存器，避免旧实现单个 `32768` lane 向量导致的大 live range；
- 默认形状改为真实层扫描最优的
  `block_rows=2, num_warps=2, chunk_cols=512`；
- 保持 Q4_K 头部、scale/min 和 code 解码精确一致；
- 对非法 `chunk_cols` 在 GPU 上传前拒绝。

`src/resident_tiled_ffn.py`

- 非 resident 路径使用三槽 copy/compute producer-consumer ring；
- tile 的 async copy ticket 在释放前显式完成，避免下一次运行读取已经被回收的
  过期 ticket；
- `pipeline_depth=1/2/3` 都覆盖数值正确性和重复运行后的资源回收。

`scripts/benchmark_resident_ffn_pipeline.py`

- 报告动态 H2D 的 activation/base-result 分项；
- 将 residual 权重 H2D 计为实际 traffic delta；
- 使用每个样本的 event span 计算 gap，避免“各自中位数相减”产生伪 gap；
- 明确这些字段不是 SM occupancy、DMA engine counter 或端到端 tok/s。

`scripts/profile_resident_cuda_graph.py`

- 自动识别 Q4_K 与 IQ4_NL down；
- 固定形状的 resident GPU-base 路径可以将 activation copy、group sum copy、
  fused gate/up/base/SwiGLU 和 down 一起 capture/replay。

其中 CPU main/base 分支约 `0.861 ms`，与 residual 分支并行；当前样本中仍有


该图路径不传 gate/up base 向量，运行时只传 host activation 和 160 个 group
sums；完整 GPU activation chain 则可使 activation/base H2D 都为 `0 B`。

## DMA 与串行的结论

1. CPU-base 路径的动态 copy 使用 pinned memory 和 `non_blocking=True`，其
   event 量级为 activation `~0.02 ms`、base result `~0.05 ms`，远低于
   residual/down kernel。
2. GPU-resident chain 没有运行时 activation/base H2D；因此不能把该路径的
   GPU 时间归因为“没有硬件 DMA”。
3. gate/up 必须先形成 SwiGLU，down 才能消费它；这是 FFN 的真实数据依赖，
   不能通过 stream/event 并行化掉。
4. `0.3~0.5 ms` 可以出现在单独的轻量 down 或更低比特、不同尺寸路径；本层
   还包括一次 `17408 x 5120` gate/up residual GEMV 和一次
   `5120 x 17408` Q4_K down GEMV。Q4_K 的 decode、显存读取和 batch=1
   reduction 仍是单层设备时间主体。

Nsight Compute 2022.3 可以启动目标程序，但本机 driver 拒绝性能计数器访问：

```text
ERR_NVGPUCTRPERM:
The user does not have permission to access NVIDIA GPU Performance Counters.
```

因此本轮不声称 SM occupancy、memory-pipe utilization 或 DMA-engine counter。
本轮数字仅来自 CUDA event、主机 wall clock、显式 traffic ledger 和数值参考。
