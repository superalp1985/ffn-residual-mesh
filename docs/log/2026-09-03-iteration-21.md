# 2026-09-03 Iteration 21

## 目标

验证 Windows 分页式“集约化成块搬运”在真实 layer 23 artifact 上是否减少 H2D 调用开销：

- 基线：`base`、`coeff`、`indices` 三次异步 H2D。
- packed：CPU 先拼成连续 pinned packet，再一次异步 H2D；GPU 按固定偏移读取。

## 先行调研

本轮仍遵循 CUDA 的 page-locked host memory + asynchronous stream 约束。连续 packet 只改变传输布局，不改变 `y_hat = base + mu_r + U alpha` 公式；因此必须同时验证数值等价与端到端 pipeline 时间。

## 实现

在 `src/cuda_probe/ffn_artifact_probe.cu` 中新增：

- `merge_packed_kernel`：从单一 packet 按 `base_bytes/coeff_bytes` 偏移解释三段数据。
- `benchmark_packed`：连续 pinned packet、单次 H2D、同一 merge 公式。
- packed kernel 的 64-token 独立输出校验。

## 结果

GPU 数值：

- 分离 kernel 相对 fp16 reference：`mean rel-L2 = 0`。
- packed kernel 相对 fp16 reference（64 token）：`mean rel-L2 = 0`，`max abs = 0`。
- 近似输出相对真实捕获 FFN：`mean rel-L2 = 2.2577%`，`p95 = 4.4973%`。

单次运行 64-token 窗口：

| 模式 | H2D ms | merge ms | pipeline ms | pipeline ms/token |
|---|---:|---:|---:|---:|
| 分离三次 H2D | 0.0558 | 0.0592 | 0.1150 | 0.00180 |
| 连续 packet 单次 H2D | 0.0484 | 0.0427 | 0.0911 | 0.00142 |

单次运行中 packed 的 H2D 低约 `13.2%`，pipeline 低约 `20.8%`。此前运行曾出现相反方向，说明当前微基准受 GPU 负载、事件计时和 launch 抖动影响；不能把单次结果视为稳定加速。

同一可执行文件连续重复 5 次、每次内部 warmup 20 + measured 200，取 64-token 窗口中位数：

| 指标 | 分离三次 H2D | 连续 packet | packed 相对变化 |
|---|---:|---:|---:|
| H2D ms | 0.05203 | 0.04823 | -7.3% |
| pipeline ms | 0.08910 | 0.08962 | +0.6% |

重复结果表明：连续 packet 稳定减少了 H2D 部分，但当前 packed kernel 的额外地址解包基本吃掉端到端收益。

## 结论

1. 连续 packet 公式与分离布局逐元素等价，布局改造没有引入额外误差。
2. 单次 H2D 的中位数下降约 `7.3%`，支持“CPU 预展开后按块搬运”的系统方向，但目前还没有端到端加速。
3. 现有 packed kernel 需要 GPU 端偏移解包；下一轮应让 CPU 直接写成 kernel 友好的对齐布局，或使用 16-byte 对齐 header/stride，减少 GPU 地址计算。
4. 近似包仍为 `4,112 B/token`，常驻残差基底为 `266,240 B`；传输量级优势不变。
