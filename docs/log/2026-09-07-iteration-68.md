# Iteration 68: Controlled Base Reduction Tuning

Date: 2026-09-07

## Objective

Tune the tiled GPU reduction of the input-dependent affine base term without
changing the exact Q4/Q5 residual split. The experiment changes only the
number of coefficient groups accumulated per loop; all base coefficients,
residuals and group sums remain present and exact.

This is a kernel-resource experiment, not a compression step. It does not
claim that the CPU-base path, full-model residency, attention/KV cache, DMA
overlap or generation throughput has been solved.

## Research and Protocol

Before implementation, the CUDA Best Practices guidance on register
pressure/occupancy and the Triton fused-kernel tutorial were checked. The
relevant constraint is that lower register use or higher theoretical
occupancy does not by itself prove lower wall time or higher achieved SM
utilization.

The runner was extended with `base_block_groups`, accepted values
`8, 16, 32, 64, 128, 256`, while retaining `256` as the default. CUDA graphs
were used to isolate repeated device work. Each candidate was compiled before
timed warmup, run in randomized order across three passes, and measured as:

- gate/up fused kernel graph;
- complete synthetic FFN graph including the original quantized down
  projection;
- resource metadata (`registers_per_thread`, spills and shared memory);
- numerical error against an independent FP64 GGUF dequantization oracle.

The graph span is a device-work timing, not an SM active-time or DMA-engine
measurement. The fixed graph input makes dynamic H2D traffic zero in this
benchmark.

## Decision

Keep `base_block_groups=256` as the public default. The smaller loop tiles do
not show a repeatable win across both real Qwen3.8-27B layers, and the complete
FFN graph remains dominated by the down projection and scheduling variability.
The current evidence is sufficient to stop this narrow tuning branch without
changing the algorithm or introducing a more fragmented residual feed.

Next performance work should instrument actual asynchronous copy/compute
overlap and end-to-end token execution. It must not infer DMA utilization,
occupancy or 20 tokens/s from these graph medians.
