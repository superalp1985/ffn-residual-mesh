# Iteration 62: IQ4_NL 单 kernel 与 DMA 边界复核

日期：2026-09-06

## 本轮目标

验证“单层 FFN 慢是因为层间严格串行、GPU 没走硬件 DMA”的判断，并先消除
down 投影内部可以直接消除的 kernel 边界。

## 调研结论

- CUDA event/stream 只记录和表达依赖，不会自动消除层间数据依赖。
- 异步 H2D 需要 pinned host memory、copy stream 和 compute-stream event wait；
  常驻 GPU activation 路径没有 H2D，因此也没有 DMA 可启用。
- CUDA Graph 主要减少重复提交开销，不减少 GEMV 算术和显存读取。

## 实现

`src/resident_residual_cuda.py`

- 新增 `_fused_iq4nl`；
- IQ4_NL 的 16-bit half scale 正确合并后解码；
- K 维分块在寄存器中累加，删除 `partial` 写回和 `torch.sum` 归约；
- 保留 `chunk_cols` 作为 K tile 大小控制参数。

`scripts/benchmark_resident_device_chain.py`

- 分开记录主机逐层同步、链尾一次同步、显式异步三种模式；
- 正式链路使用 `measure_events=False`，避免每层创建多组计时 event。
- 删除同一 CUDA stream 上对自身 `base_end` event 的冗余 `wait_event`。

## 判断

当前证据不支持“常驻路径没有使用 DMA”这一归因，因为常驻路径没有运行时
activation/base H2D。`0.3~0.5 ms` 已在单独 down kernel 上出现，但完整单层
FFN 仍约 `1.9~2.0 ms`，主要由 batch=1 量化 gate/up GEMV、down GEMV 和天然
层依赖决定。

下一轮应优先评估 CUTLASS/cuBLASLt 友好的 int4 GEMV 布局、解码与点积融合，
以及非 resident tile 的 copy/compute 双缓冲；不能把 host enqueue 或 DMA
问题与设备端 GEMV 算术混为一谈。
