# Iteration 65: Grouped Q4_K Down Decode and Steady-State Timing

Date: 2026-09-06

## Question

Determine whether the remaining Qwen3.8-27B Q4_K layer-21 FFN time is caused
by fragmented H2D/DMA submission, or by the two quantized batch-1 GEMV stages.

The project goal remains unchanged:

1. CPU evaluates the static base branch from host-resident expanded data.
2. GPU keeps residual codes/scales resident after cold start.
3. GPU receives only activation and merged base vectors at runtime.
4. The measurement must distinguish cold-clock behavior from steady inference.

## Prior Art Boundary

CUDA asynchronous copies require page-locked host storage and a stream-aware
submission path. CUDA Graphs reduce repeated launch/submission overhead but do
not remove actual data dependencies or Q4_K decode work.

References:

- NVIDIA CUDA C Best Practices Guide:
  https://docs.nvidia.com/cuda/cuda-c-best-practices-guide/index.html
- NVIDIA CUDA C Programming Guide, asynchronous execution and CUDA Graphs:
  https://docs.nvidia.com/cuda/cuda-c-programming-guide/index.html

This project uses pinned host staging and `non_blocking=True`. CUDA event spans
are used only for stream timing; no SM occupancy, DMA-engine utilization, or
memory-pipe utilization is claimed because the local driver denies Nsight
Compute counter access.

## Implementation

`src/resident_residual_cuda.py`

- Added exact `_fused_q4k_grouped`.
- Each program decodes a Q4_K 256-value block as four 64-value nibble pairs.
- The FP16 `d/dm` header is loaded once per Q4_K block.
- Each packed code byte is loaded once, producing both low/high nibbles.
- The original GGUF Q4_K scale/min formula remains unchanged.
- `DirectQ4Projection` now supports `kernel="grouped"` and
  `block_qblocks=1|2|4`.

`ResidentGateUp`

- Added grouped residual decode candidates.
- `grouped_fused` evaluates gate/up residuals in one kernel and shares the
  activation load.

`scripts/benchmark_resident_ffn_pipeline.py`

- Supports explicit residual and Q4_K down kernel configurations.
- Records `warmup_seconds_requested` and `warmup_runs`; a measured steady-state
  run must not mix cold-clock ramp-up into the inference median.

Exact Q4_K down kernel-only CUDA-event scan:

```text
legacy best:  block_rows=2, warps=2, chunk_cols=512, 0.669 ms median
grouped best: block_rows=2, warps=2, qblocks=4,   0.412 ms median
```

This is a 38% kernel-only median reduction. It comes from reducing repeated
header/code-byte decode work, not from changing the model or dropping
arithmetic.

## Steady Full FFN

Configuration:

```text
gate/up residual: grouped_fused, block_rows=8, warps=4, groups=16
down: grouped Q4_K, block_rows=2, warps=2, qblocks=4
warmup: 2 s / 1114 full runs
measured samples: 51
```

Median:

```text
CPU base                         0.337 ms
gate/up residual CUDA span       0.499 ms
SwiGLU merge                     0.023 ms
Q4_K down CUDA span              0.402 ms
CUDA stream span                 1.052 ms
exposed CPU submission gap       0.001 ms
wall                             1.107 ms
output relative L2               2.48e-7
dynamic H2D                      159,744 B/token
resident weight H2D warm run     0 B/token
resident FFN payload             161,546,240 B
```

The Q4_K `down` and resident gate/up residual stages individually reach the
0.3--0.5 ms range. Their sum cannot be reduced to one such interval by
streaming alone: `down` consumes the SwiGLU output, so gate/up -> SwiGLU ->
down is a real dependency chain.

Some samples still show a higher timing mode (roughly 0.9--1.1 ms residual or
0.6--1.0 ms down). It is not accompanied by a material CPU submission gap.
The local RTX 4070 Laptop GPU returns to P5 / about 435--465 MHz after the
short benchmark finishes, so these outliers are recorded as system/power
variability rather than attributed to a missing DMA path.

## Decision

1. Do not pursue tiny per-tile H2D packing as the current main bottleneck.
   The residual payload is resident, runtime H2D is already two compact
   vectors, and the steady CPU submission gap is about 1 microsecond.
2. Keep the grouped Q4_K down implementation as the preferred exact candidate
   for the measured layer shape, but retain the legacy implementation for
   comparisons until more layers have been scanned.
3. The next performance work should target cross-layer steady execution and
   variance: graph/ring submission across a layer window, plus representative
   layers rather than only layer 21.
4. This remains a one-layer synthetic-activation experiment. It is not an
   end-to-end Qwen token/s result and does not include attention, KV cache,
   layer-window paging, sampling, or model-quality evaluation.
