# 2026-09-03 Iteration 20

## 目标

把真实 layer 23 的离线残差 artifact 接入 CUDA 原型，分离验证：

1. GPU 合并实现是否与 fp16 公式一致。
2. fp16 公式相对真实捕获 FFN 的近似误差。
3. 真实包在 1/16/64 token 窗口下的 H2D 与 merge 成本。

## 先行调研

- 本轮先核对 CUDA Runtime 的异步 H2D 约束：`cudaMemcpyAsync` 要获得真正异步行为，host 源内存应使用 page-locked/pinned allocation；stream 与 event 用于建立 copy/compute 顺序和计时。
- `E:\MiniMaxH3\ComfyUI\venv` 实测为 PyTorch `2.9.1+cu130`，CUDA runtime `13.0`，GPU 为 RTX 4070 Laptop；本机 nvcc 工具链仍为 CUDA 11.8，使用 `sm_89` 编译运行。

## 实验实现

新增：

- `scripts/export_cuda_residual_artifact.py`
- `src/cuda_probe/ffn_artifact_probe.cu`

artifact 包含真实 holdout 的：

```text
fp16 base
fp16 top-k residual coefficients
uint16 residual indices
fp16 residual mean and basis
fp32 captured FFN target
fp32 CPU formula reference
```

layer 23 配置：Chebyshev degree=5、bound=5 sigma、input rank=128、output rank=64、top-k=4。

## 结果

真实 artifact 元数据：

- holdout tokens: `138`
- hidden: `2048`
- 常驻 `U_r + mu_r`: `266,240 B`
- 近似包：`4,112 B/token`
- Q4 down 权重代理：`10,321,920 B`

数值：

- GPU 实现相对 fp16 CPU reference：`mean rel-L2 = 0`，`max abs = 0`。
- fp16 公式相对真实捕获 FFN：`mean rel-L2 = 2.2577%`，`p95 = 4.4973%`，`max abs = 0.4452`。
- fp16 量化相对 float32 公式的误差仅约 `0.0202%`，说明主要误差来自低秩/基项近似，而非 H2D 或 fp16 合并。

## 结论

1. 真实数据链路成立：CPU 预展开产物可直接被 GPU 轻量合并，公式实现无额外数值误差。
2. 2.26% 的近似误差仍是当前算法误差上限；传输格式不会显著改变它。
3. 4 KiB/token 的近似包相对约 10 MiB/token 的逐 token 精确回退，仍保持约 2,500 倍的传输量级优势。
4. 下一轮专门比较三次小 H2D 与连续 packet 单次 H2D，避免把传输格式和近似误差混在一起。
