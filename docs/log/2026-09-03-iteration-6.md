# 2026-09-03 Iteration 6

## 研究前置

本轮先复核已有路线：

- PowerInfer：热/冷神经元划分和 CPU/GPU 协同证明“只把活跃子集送 GPU”有工程可行性，但它依赖激活稀疏性，不等价于本项目的 dense FFN 状态查表。
- FlexGen：把权重、激活和 KV 按层在 CPU/GPU/磁盘间调度，说明分层内存要靠离线布局、预取、批量和双缓冲才能换来吞吐。
- T-MAC、LUT-LLM、FLUTE：查表路径的核心不是公式本身，而是离线重排、复制、位打包和批量访问；本项目不重复实现通用 LUT-GEMM。
- TARDIS 类分段线性回退路线与本项目的“局部近似 + OOD 精确回退”最接近，但 Qwen3.5 的 SwiGLU 非线性交叉项需要单独验证。

本轮因此不修改 llama.cpp 核心图执行器，先用真实捕获的 layer 输入/输出验证运行时公式和门控成本。

## 实验假设

对固定层、状态中心 `c_k`，拟合：

```text
y_hat = base_k + U_k @ (V_k^T @ (x - c_k))
```

其中 CPU 负责最近中心搜索和 rank-r 系数生成，GPU 常驻 `base_k/U_k`；距离超过阈值时走精确 FFN。该式绕开了“先算 SwiGLU 再查表”的额外显存往返，直接对应输入侧运行时。

## 数据与环境

- 模型：Qwen3.5-2B-Q4_K_M，24 层，hidden=2048，FFN intermediate=6144。
- GPU：RTX 4070 Laptop 8 GiB；CPU：i7-14650HX；llama.cpp build `0eca4d490`。
- 校准：`results/calibration_v2_20260903`，655 samples/layer。
- 留出：`results/calibration_holdout_v2_20260903`，138 samples/layer。
- 运行脚本：`scripts/evaluate_input_local_residual.py`。

## 结果：layer 23

| rank | 留出全量近似 rel-L2 | 近似比例（训练 p95<=0.20） | 混合 rel-L2 | CPU 路由 us/token |
|---:|---:|---:|---:|---:|
| 8  | 0.342 | 0.00 | 0.000 | 41.8 |
| 16 | 0.313 | 0.181 | 0.021 | 42.8 |
| 32 | 0.286 | 0.297 | 0.034 | 47.4 |
| 64 | 0.268 | 0.507 | 0.088 | 56.6 |

按训练集距离门控、在留出集统计时，rank=64 的约 50.7% token 走近似、49.3% 精确回退，混合输出 rel-L2=0.0877。全量近似仍有 0.268，不能直接替代精确 FFN。

## 结果：layer 22

layer 22 明显更差：rank=64 全量近似留出 rel-L2=0.242；在训练 p95<=0.20 门控下，约 0.0%--0.2% token 可稳定近似。即使放宽到 p95<=0.50，近似比例约 0.225，混合 rel-L2 约 0.068。说明算子必须按层选择，不能把 layer 23 策略复制到全模型。

## 搬运代理

`scripts/estimate_hybrid_transfer.py` 使用每层 FFN 权重 23 MB、输入 8,192 B、256 KiB 超级块估算：

- rank=64、layer 23、训练 p95<=0.20：约 50.7% 近似，理论 H2D 权重流量相对完整权重下降约 50.7%；近似 token 只传约 257 B 的 code+coeff，另有 8 KiB 输入 D2H。
- rank=64、训练 p95<=0.30：约 96.4% 近似，理论权重流量下降约 96.4%，但输出误差约 0.242，暂不接受。
- 超级块页舍入对 batch=1 会放大回退流量；连续 token 批量和 pinned ring buffer 是后续必测项。

这些数字是带宽代理，不是 CUDA 实测；没有计入 kernel launch、同步和 CPU/GPU 排队。

## 结论

1. “预展开 + CPU 路由 + GPU 小残差 + 精确回退”在 layer 23 已出现可用的局部窗口，但不是全量替代。
2. 输入侧局部低秩比静态输出 LUT 更符合运行时，但 rank 增大后 CPU 路由成本上升，且分布外误差仍受限。
3. layer 22/23 差异验证了按层算子适配的必要性；全模型应先只替换少数稳定层。
4. 下一轮要做真实 llama.cpp callback 注入：捕获 `ffn_out-23` 后原位替换近似值，读取 logits/KL，并统计实际 GPU/CPU 时间。若 callback 注入不稳定，再退回独立 replay harness。
