# 2026-09-05 Iteration 48: Complete FFN Phone Offload Baseline

## Question

If a tablet or old phone stores a complete FFN layer, computes the whole FFN locally, and returns only the post-down hidden result, is that more practical than CPU lookup tables?

## Implementation

- Added `scripts/simulate_full_ffn_phone_offload.py`.
- Added `src/full_ffn_loopback.py`.
- Added tests for numerical equivalence, text activation traffic, and video boundary cost.

The loopback worker executes:

```text
input hidden -> gate/up -> SiLU(gate) * up -> down -> output hidden
```

The returned fp16 output matches direct CPU fp32 execution within the expected fp16 transport tolerance.

接近 Qwen3.5 2B layer-23 的本机 NumPy loopback（hidden=2048, ffn=6144, batch=1）结果：直接 CPU FFN 约 `2.57 ms`，loopback 完整 FFN 约 `3.54 ms`，fp16 往返相对 L2 约 `3.66e-4`。这是本机进程协议和 NumPy 的基线，不是 Android 或 USB 实测；它证明了完整 FFN worker 的数据边界和数值路径可以先独立验证。

## Qwen3.5 2B text budget

Assumptions: hidden=2048, FFN=6144, 24 layers, batch=1, fp16 activation, 10 Gb/s wired link.

- Complete FFN roundtrip: 8 KiB per layer.
- All 24 layer boundaries: 192 KiB per token.
- Approximate Q4 gate+up+down weight volume: 432 MiB for all 24 layers.
- With a 2 ms phone FFN time per layer, total estimated latency is 67.0 ms/token.
- With a 0.25 ms phone FFN time per layer, total estimated latency is 26.5 ms/token.

The link is not the main issue for batch-1 text. Phone compute and 24 serial layer boundaries are the main issue. Additional phones reduce per-device resident weight volume, but do not divide a single dependency chain.

## MiniMax H3 video budget

Assumptions: 15,356 packed rows, hidden=5376, 50 FFN boundaries, fp16 activation.

- One complete FFN input/output roundtrip: about 314.9 MiB.
- Fifty boundaries: about 15,745.9 MiB per forward.
- At 10 Gb/s, transport alone is about 13.2 seconds before phone compute.

Therefore full FFN layer offload is a plausible text-model baseline, but direct layer-by-layer phone offload is not automatically suitable for H3 video. H3 needs larger chunks, a device-side block/attention boundary, stronger compression, or the original residual strategy.

## Decision

Keep complete FFN offload as the first real wired-device prototype because its protocol and correctness path are simple. Use it to measure actual tablet throughput and thermal stability. Keep base+residual as the higher-complexity path for workloads where the center GPU must retain more of the FFN arithmetic.
