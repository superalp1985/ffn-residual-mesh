# 2026-09-05 Iteration 46: MiniMax H3 ComfyUI Phone FFN Simulation

## Question

Can a phone/tablet pool host MiniMax H3 FFN base terms while the center RTX 4070 keeps SageAttention, residual, SwiGLU and down projection, with TeaCache reducing the number of real DiT forwards?

## Local facts

- ComfyUI 0.30.0
- Python 3.12.10
- torch 2.9.1+cu130, torch.version.cuda=13.0
- NVIDIA GeForce RTX 4070 Laptop GPU
- MiniMax H3 diffusion model: int8 convrot
- 50 blocks
- fc1: [28672, 5376] int8
- fc2: [5376, 14336] int8

## Workload

- width=832, height=480, requested frames=124
- H3 aligned frames=124
- video rows=14,430
- audio rows=414
- text rows=512
- packed rows=15,356
- 20 sampling steps
- TeaCache assumption: 8 real steps, 12 reused steps
- reference real step: 12.33 s from local H3 logs

## Simulation command

~~~powershell
python scripts/simulate_comfyui_phone_ffn.py --width 832 --height 480 --frames 124 --steps 20 --tea-real-steps 8 --network-gbps 1 --phone-return gate_up_exact --out results/comfyui_h3_phone_exact_1gbps.json
~~~

## Main result

Exact gate/up base return is about 839.8 MiB per real step. At 1 Gb/s, network return is about 7.04 s per real step. The phone branch remains critical even with 64 workers; estimated total is about 116.7 s versus 114.2 s for the same TeaCache schedule without the phone backend.

At 10 Gb/s, exact gate/up return is about 0.74 s per real step and is hidden under the modeled GPU branch. Estimated total stays about 114.2 s; this is a feasibility result, not a speedup claim.

The hidden-return variant is about 157.5 MiB per real step at 1 Gb/s, but it is not algebraically exact and must be treated as an approximate path with error measurement and fallback.

## Conclusion

- ComfyUI integration is architecturally possible through a model wrapper/custom node.
- TeaCache and SageAttention remain compatible and should stay on the center GPU.
- Ordinary Wi-Fi is not a suitable exact gate/up online transport for this H3 video workload.
- First real prototype should be loopback workers, then USB/10GbE tablet, then phones.
- Keep GPU exact fallback and audio guard. Do not force the phone backend into the default 124-frame AV workflow before deadline and quality tests pass.
