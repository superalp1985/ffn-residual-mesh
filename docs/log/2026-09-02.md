## 离线 GGUF/布局扫描

- `gguf` Python 读取器成功读取 320 个张量和 49 个元数据字段。
- 模型结构：24 层，hidden=2048，FFN intermediate=6144，包含 `ssm_*` 与 `attn_*`。
- FFN 张量总量：523.125 MiB，占 GGUF 张量字节 43.20%。
- 每层 FFN 量化后大小有两档：23.3438 MiB 或 20.25 MiB。
- 若以 256 KiB 超级块搬运，每层约 81--94 块；以 1 MiB 超级块约 21--24 块。

结论：分页目录应以“层 + 张量 + 连续超级块”为主键，不能只按统一页大小切割；Qwen3.5 混合结构必须为 SSM/Attention/FFN 分别保留布局统计。

## 分页模拟

- 脚本：`scripts/simulate_paging.py`，固定随机种子 `20260902`。
- 在 64 KiB 逻辑页、10% 请求比例下，256 KiB 超级块的平均浪费约为：随机请求 2.409 倍，集群请求 0.076 倍。
- 同一条件下，1 MiB/4 MiB/16 MiB 超级块对随机请求的平均浪费约为 7.190/8.773/8.824 倍；对集群请求约为 0.411/1.648/6.591 倍。

结论：超级块必须建立在路由局部性之上。首选 256 KiB--1 MiB，并在运行时合并相邻请求；如果路由近似随机，大块搬运会反而放大带宽浪费。

## 当前假设
