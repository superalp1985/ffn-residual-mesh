# 2026-09-03 Iteration 17

## 目标

测量 CPU 侧精确 FFN、Chebyshev 基础项和残差系数生成的 decode 风格耗时，判断“增加算力”是否会成为新瓶颈。

## 方法

- NumPy 单 token、fp32 解量化权重。
- 16 个留出 token，单次重复；结果只用于量级判断。
- 未包含 GPU residual merge、pinned H2D、PCIe 和 kernel launch。

## 结果

| 层 | 精确 FFN median | Chebyshev base median | 残差系数 median |
|---|---:|---:|---:|
| 10 | 2.25 ms | 2.65 ms | 12.0 μs |
| 22 | 2.16 ms | 2.49 ms | 11.5 μs |
| 23 | 2.26 ms | 2.43 ms | 11.2 μs |

layer 23 候选的算力代理：

- gate/up/down 三次投影共约 `37.75M MAC/token`。
- 残差输入投影约 `0.26M MAC/token`。
- GPU top-k=4 合并约 `8,192 MAC/token`。

## 结论

1. 残差路由和 top-k 选择的 CPU 成本约为 FFN 的千分之几，不是瓶颈。
2. Chebyshev 基础路径比精确 SiLU 路径慢约几百微秒，但仍由三次矩阵乘主导；这是以 CPU 算力换 GPU 动态权重搬运的可接受量级。
3. 真实端到端收益仍取决于 GPU 是否能并行处理残差 merge，以及近似包是否通过 pinned ring buffer 合并传输。
4. 当前微基准不能证明整体加速；下一步必须在 llama.cpp 或独立 CUDA 原型中实测 H2D、GPU kernel 和同步。
