# 2026-09-03 Iteration 12

## 目标

把 monomial 基底替换为有界 Chebyshev 基底，检查前几轮把某些层判为“不适合”是否其实是数值基底不稳导致的。

## 公式

```text
t_j = clip((g_j - mu_j) / (sigma_j * B), -1, 1)
h0_j = u_j * sum_p c[j,p] T_p(t_j)
```

`T_p` 使用递推生成，不查表、不调用运行时 SiLU。`B` 是离线校准得到的标准差倍数；当前测试 `B=6`。

## 结果

仅基础项、degree=4、bound=6σ：

- layer 23 留出输出 rel-L2：`0.02546`，优于 monomial degree=4 的 `0.02829`。
- layer 22 留出输出 rel-L2：`0.04999`，显著优于 monomial 的 `0.07833`。

接入 capture-target 残差后：

- layer 23：`input_rank=128, output_rank=64` 时留出 rel-L2 `0.02397`；只保留 4 个残差系数时约 `0.02427`。
- layer 22：完整 64 个系数时约 `0.04779`；4 个系数时约 `0.04847`。

这两层均可在 4 个残差系数下维持接近完整系数的误差，近似路径仍只需约 `4.1 KiB/token`（含 2048 维 fp16 基础输出和掩码/系数），GPU 常驻基底约 `32 KiB`（4 个输出基向量）到 `256 KiB`（64 个）。

## 结论

1. “不适合层”不能只由某一种多项式基底判断；Chebyshev 的区间约束显著改善 layer 22。
2. 当前默认基础公式应从 monomial 改成可配置的 Chebyshev；`B` 和 degree 必须逐层选择。
3. layer 22 虽然改善到约 4.8%，仍高于 layer 23，不能直接共享参数或统一阈值。
4. Chebyshev 递推增加少量乘加，但没有引入查表，符合“以算换带宽”的目标。
