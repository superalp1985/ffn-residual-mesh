# 2026-09-04 Iteration 36: CUDA Residual Tile Runner

## Research first

Reviewed NVIDIA CUDA documentation for:

- `cudaMemcpyAsync` and the requirement for page-locked host memory;
- non-default streams and asynchronous copy/execute overlap;
- `cudaStreamWaitEvent` cross-stream dependency scheduling.

The implementation follows the documented staged pipeline: pinned host tile, copy stream, compute stream, CUDA events, and two reusable device buffers.

## Implementation

Added:

- `src/exact_residual_cuda_runner.cu`
- `scripts/build_and_run_cuda_residual_runner.py`

The runner reads only the compiled QLO2 residual artifact and activation state. It does not open the GGUF model. Each tile combines row-packed 2-bit codes and fp32 alpha into one H2D packet.

## Results

At 1024 rows, representative run:

| projection | copy-only | kernel-only | serial copy+kernel | double-buffer overlap | speedup |
|---|---:|---:|---:|---:|---:|
| gate | 0.384 ms | 0.112 ms | 0.727 ms | 0.612 ms | 1.19x |
| up | 0.384 ms | 0.103 ms | 0.795 ms | 0.516 ms | 1.54x |
| gate + up | - | - | 1.522 ms | 1.129 ms | 1.35x |

The 11-repeat tile sweep showed the same direction. Pair overlap speedup ranged from about 1.09x at a whole-layer tile to about 1.80x at 512 rows. Absolute latency was lowest around 2048 rows in that run, while 512–1024 rows gave the strongest overlap ratio. GPU clock/power-state variation is large enough that future comparisons should use paired runs in one process.

## Decision

Continue. The exact residual path is numerically correct and double buffering reduces the copy/launch critical path. However, residual computation is only about 0.1–0.3 ms while H2D is about 0.4–0.75 ms, so residual arithmetic alone cannot hide all transfer time. The decisive experiment is CPU main-term evaluation concurrent with GPU residual evaluation.
