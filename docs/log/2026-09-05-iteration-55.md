# Iteration 55: Tile-Grained Residual Prefetch

Date: 2026-09-05

## Findings

Whole-layer residual package prefetch is too coarse. On the RTX 4070 Laptop,
one Qwen3.8 layer-3 gate/up package is about `111.4 MB`; its H2D copy is about
`8.8-10.9 ms`, while a single residual kernel is below `1 ms`. A whole-package
copy cannot be fully hidden by one residual kernel.

## Implementation

- Added `TilePlan` for exact row-range partitioning.
- Added `ResidentTileCache`, which uses the existing scheduler and CUDA cache
  with independent gate/up row tiles.
- Added `launch_residual_tile`, reusing the exact signed-nibble residual dot
  kernel for one tile.
- Added transfer and overlap benchmarks.

## Measurements

For Qwen3.8-27B layer 3, gate/up exact artifact:

| tile rows | tile count | tile bytes | warm wall | tile kernel sum | H2D total |
|---:|---:|---:|---:|---:|---:|
| 256 | 68 | 1.64 MB | 21.1 ms | 4.90 ms | 11.84 MB |
| 512 | 34 | 3.28 MB | 17.6 ms | 3.94 ms | 11.39 MB |
| 1024 | 17 | 6.55 MB | 13.3 ms | 2.25 ms | 10.68 MB |

The warm 1024-row result is a real residual tile kernel with next-tile async
prefetch. It excludes the CPU base term, SwiGLU, down projection, attention,
KV cache, and generation. The first-run numbers include Triton compilation and
must not be used as steady-state performance.

## Interpretation

Tile partitioning reduces exposed host serialization and creates a viable
overlap structure, but it does not reduce total H2D bytes. The next optimization
must reduce exposed copy time through larger useful compute per tile or a
fused/tiled FFN path. Smaller tiles are not automatically better because launch
overhead grows quickly.
