# Iteration 58: Multi-Layer Persistent Set Selection

Date: 2026-09-05

## Policy

Added a deterministic weighted-hit-density selector for persistent FFN layer
packages. The selector reserves space for the active and prefetched windows
before choosing layers, so persistent residency cannot consume the entire swap
budget.

For the Qwen3.8-27B manifest with an 8 GiB VRAM budget, 1 GiB fixed reserve,
and a 4-layer active/prefetch window:

- FFN capacity after fixed reserve: `7,516,192,768` bytes;
- conservative two-window working set: `1,494,302,720` bytes;
- persistent-set capacity: `6,021,890,048` bytes;
- selected persistent layers: `41 / 64`;
- estimated uniform-trace coverage: `64.06%`;
- simulated blocked prefetches: `0`.

The simulation uses original GGUF FFN bytes for uncompiled fallback layers and
an estimated compiled multiplier for the five currently compilable gate/up
layers. It is therefore a capacity and policy result, not a runtime throughput
measurement.

## Important Result

Selecting persistent layers without subtracting the swap window overcommits
VRAM and causes prefetch failure. Reserving the window first makes the policy
operational, at the cost of fewer persistent layers.
