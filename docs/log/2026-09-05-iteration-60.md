# Iteration 60: fixed-shape CUDA Graph replay

## Objective

Reduce repeated launch, event, and stream scheduling gaps after the residual
feed has already been made a dense resident super-tile.

## Implementation

- Added optional `use_cuda_graph=True` to `TiledResidentGateUp`.
- Captures fixed pinned-buffer H2D copies, fused base/residual/SwiGLU, and an
  optional resident IQ4_NL down projection.
- Replays only when the layer is a full resident super-tile and the same down
  object is used. Multi-tile and swapped paths remain unchanged.
- Added correctness tests for new activations and graph-captured down.
- Fixed the ordinary down path so its launch and timing events are recorded on
  the compute stream.

## Measurement

RTX 4070 Laptop, Qwen3.8-27B Q4_K_M, single-token warm layer path:

| Layer | Ordinary fused + down | CUDA Graph fused + down |
|---|---:|---:|
| 3 | ~1.93 ms | ~1.80 ms |
| 21 | ~2.30 ms | ~2.20 ms |

The first graph replay includes capture/cold-start work and is not a steady
state number. The graph path preserves the tested output and does not reduce
the arithmetic count; it targets scheduling bubbles.

The local Nsight Compute 2022.3 binary launched but returned
`ERR_NVGPUCTRPERM`, so no occupancy or pipe-active values are reported. The
reproducible profiling entry point is
`scripts/profile_resident_cuda_graph.py`.
