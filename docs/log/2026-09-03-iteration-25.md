# 2026-09-03 Iteration 25

## 目标修正

用户明确指出：本项目所说的“展开权重后拆分、计算残差、再合并”，不是以 VQ 码本近似输入，更不是要求一个覆盖所有层的通用解析式。

目标改为每层、每个分区拥有自己的公式表：记录固定权重如何拆为臃肿基项和锯齿残差、各项在哪里计算、以及如何以尺度/进位规则合并。公式可分段、离散、非线性或表驱动。

## 主公式

在选定固定点整数域，令：

```text
x = Bx*x_hi + x_lo
w = Bw*w_hi + w_lo
```

则每个点积必须保留：

```text
x*w = Bx*Bw*sum(x_hi*w_hi)
    + Bx*sum(x_hi*w_lo)
    + Bw*sum(x_lo*w_hi)
    +    sum(x_lo*w_lo)
```

这就是本轮的拆分公式与合并不变量。只要四项和缩放规则均被执行，`g/u` 在此整数域中与原投影等价；SiLU 和 down 投影在合并后保持原算子。

## 调研与判断

- 已有 LUT/VQ 路线证明预计算和布局能提高计算密度，但它们通常以激活近似为核心，不应取代本项目的算术等价主线。
- 位拆分本身不自动节省带宽：若高位矩阵仍然无结构且不在 GPU，就仍要逐项读取。它只提供正确的重组方式。
- 因此冷启动展开的核心筛选条件变为：高位/基项能否编译为块共享、位平面、低秩、分层或其他由少量输入聚合量执行的结构；否则该规则虽等价但无系统价值。

## 后续澄清：先数学，后系统

用户要求暂停大规模搬运和性能实验，优先解决“一个很长的权重数字怎样拆得合理、允许误差时怎样合并回来”的数学问题。该优先级高于当前的 W4A8、分页和 PCIe 验证。

因此新增 `docs/weight_code_split_spec.md`。它以 Q4_K 的实际形式为起点：

```text
w[j,g,i] = a[j,g] * q[j,g,i] - c[j,g]
```

并定义每个权重分区的通用拆分：

```text
q[i] = C[h[i]] + r[i]
sum(z*q) = sum_k C[k] * sum_{i:h[i]=k}(z[i]) + sum(z*r)
```

`C`、`h`、`r` 均从固定权重离线生成。这里的表是权重码的转换/合并表，不是运行时按激活状态检索的 VQ 码本。

数学上有三类候选：

1. 居中进制：`q = b + B*h + r`。
2. 非均匀整数值表：`q = C[h] + r`。
3. 分层块基项：`q = b32 + b8[subblock] + C[h] + r`。

完整保留 `r` 时，三类均在 Q4_K 的整数码域严格等价；只对 `r` 截断或再量化时才出现可单独界定的误差。SwiGLU 在 gate/up 合并后按原算子执行。

下一轮不是跑吞吐，而是用激活协方差和残差误差界为每个 32 值组枚举 `C`、`B`、块层级与残差格式，先选出数学和字节账本都合理的公式表。

## 用户提出的分区居中恒等式

用户提出 `(a+b)*(c+d)` 的方向：让大整数基项保留，只对小残差项做重计算。将其改写为一个可用于点积的严格公式后，设一个 32 值分区：

```text
x[i] = a + b[i]
q[i] = c + d[i]
```

则：

```text
sum(x*q) = 32*a*c + a*sum(d) + c*sum(b) + sum(b*d)
```

选择分区均值 `a = mean(x)`、`c = mean(q)` 时，`sum(b)=sum(d)=0`，因此：

```text
sum(x*q) = 32*a*c + sum(b*d)
```

这不是忽略交叉项，而是以零和约束使其在分区累加后严格抵消。若要保持整数，保留 `B=sum(b)` 和预展开的 `D=sum(d)` 两个小聚合校正项，原式仍严格等价。

该恒等式成为下一轮主候选。它还自然给出允许误差时的界：若只近似 `d`，则局部误差为 `b^T(d-d_hat)`，不超过 `||b||_2 ||d-d_hat||_2`（再乘激活和 Q4_K 的分组尺度）。

## 共享基项的进一步收敛

用户提出让激活侧的 `a` 与权重侧的 `c` 尽量相同，以进一步增强规律性。该想法成立，但相同必须定义在共同的归一化/量化坐标系中：

```text
x = sx*(s+b)
w = sw*(s+d)
```

于是：

```text
x^T*w = sx*sw*(n*s^2 + s*sum(b+d) + b^T*d)
```

如果两边残差都零和，交叉项严格消失；如果均值不完全相同，仍只需一个分区聚合修正项。不能直接强行令原始浮点激活均值等于权重均值，否则可能把能量推入 `b*d` 残差。

更稳健的推广是共同的低秩正交基底：

```text
x = U*alpha + b
w = U*gamma + d
U^T*b = U^T*d = 0
x^T*w = alpha^T*gamma + b^T*d
```

共享标量基项只是 `rank=1` 的特例。后续数学筛选优先枚举共同标量中心和 `rank=2/4/8` 共享基底，目标同时最小化残差乘积误差、残差字节数和 GPU 规则算子成本。GPU 侧应接收固定形状、低位宽的 `b*d` 残差块，避免依赖不规则稀疏分支。

1. “分块居中”是正确的合并公式，但不是足够的压缩结构。
2. Q4_K 的有用方向不是简单统一基底，而是寻找更高层级的共享模板、位平面或规则块；否则基底仍需逐行存储。
3. 2/3-bit 残差不能无条件截断；若保留精确性，溢出元数据会吞掉收益。
4. 下一轮优先枚举跨输出行共享的 256 值码模板和按 Q4_K 子组的位平面编码，同时给出包含索引、对齐、scale/min 的真实动态字节账本。

### 位平面筛选

`scan_q4k_bitplane_structure.py` 对 layer 23 的 gate/up 统计显示，Q4_K 四个位平面二进制熵均接近 `1.0 bit/value`，32 值码模板重复率为 0，未发现可直接利用的常量位平面或跨行模板。

### 精确高低位公式

新增 `scripts/scan_q4k_bit_split_tradeoff.py`，将每个 Q4_K 4-bit 码严格拆成：

```text
q = 2^r * q_hi + q_lo
w = alpha * q + beta
```

其中 `r` 为动态低位数，`q_hi` 常驻 GPU，`q_lo` 作为动态残差包搬运；`scale/min` 元数据也常驻。layer 23 的 gate/up 结果：

| 常驻高位 | 动态低位 | GPU 常驻相对 Q4_K | 动态码流相对完整 Q4_K |
|---:|---:|---:|---:|
| 1 bit | 3 bit | -66.7% | -33.3% |
| 2 bit | 2 bit | -44.4% | -55.6% |
| 3 bit | 1 bit | -22.2% | -77.8% |
| 4 bit | 0 bit | 0% | -100% |

所有档位 holdout 投影重放误差约 `2e-7` 相对 L2、绝对误差约 `5e-6`，说明这是量化码域的严格等价拆分，而不是近似压缩。合并只需整数移位/加法，再乘原有 `scale/min`。

### 重要边界

- 这个结果证明了“用显存换带宽”在公式上可行，但若每 token 仍搬运整份低位码，GPU 只得到带宽下降，不会自动得到算子利用率提升。
- 若常驻高位码仍占 `1--3 bit/value`，显存节省与动态 H2D 节省存在明确线性权衡；建议先以 2/2 档做 kernel 原型。
- `scale/min` 必须和高位码绑定常驻，否则元数据搬运会吞掉收益。
- 当前 H2D 是“完整投影低位码每 token 一次”的保守账本；下一步要按层/输出 tile/超级块测实际请求合并、异步重叠和 GPU 等待。

## 2026-09-03 迭代 28：放置方向纠正

用户纠正了数据放置方向。主方案不是“高位或基项常驻 GPU”，而是：

```text
Host RAM / CPU: 展开基项、高位码、beta 修正、分区公式
GPU: 低位锯齿残差包和残差 dot kernel
Merge: base(x) + residual(x)，随后原始 SiLU/down
```

主机内存可以用来换冷启动时间和预展开空间；优化目标仍是少占显存、少传 H2D、提高 GPU 残差算子连续性。

`scan_q4k_host_base_gpu_residual.py` 已验证精确公式：

```text
q = 2^r*q_hi + q_lo
host_base = alpha * 2^r * dot(x, q_hi) + beta * sum(x)
gpu_residual = alpha * dot(x, q_lo)
projection = host_base + gpu_residual
```

layer 23 gate/up 的合并误差约 `2e-7` 相对 L2，说明拆分本身严格等价。若 GPU 只接收 1-bit 低位残差及预展开 alpha，gate/up 合计 GPU 残差包约 `2.25 MiB`，相对完整两份 gate/up Q4_K 的 `13.5 MiB` 少约 `83.3%`；2-bit 残差包约 `3.75 MiB`，少约 `72.2%`。

但这只是正确的资源方向和公式验证，不是性能胜利：CPU 仍需快速完成基项，且必须把 gate/up 基项向量（合计约 `24 KiB/token` fp16）与 GPU 残差在 SiLU 前合并。后续需验证 CPU 基项计算是否成为新瓶颈，并比较“CPU 上合并后传完整 gate/up”与“传基项到 GPU 合并”的实际同步成本。

### 当前结论

```text
RAM/CPU：预展开公式、Q4_K 高位/基项、beta、tile 目录

```

但“CPU 基项不逐权重扫描”尚未解决。简单均值、位拆分、跨行图样、行内子块基值都不能同时满足低残差和低 CPU 访问。后续应优先研究：

2. 输出 tile 内的结构化稀疏或低秩基项，要求真实 residual bits 和 CPU 工作量同时下降；
3. 在确认基项算子后，再接入 pinned ring buffer、异步 H2D 和真实 CUDA kernel。

## 2026-09-03 迭代 32：运行时扫描边界澄清

用户澄清：主项的完整扫描只允许发生在冷启动展开阶段；运行时不但不能重新扫描 GGUF 原始权重，也不能把“顺序扫描一份展开后的高位权重流”误称为完成目标。

因此执行边界改为：

```text
冷启动：完整扫描原始权重 -> 生成 RAM 中的公式/部分和/残差 artifact
运行时：根据动态 x 只执行公式、读取有限状态表或残差 tile
禁止：按 token 枚举主项的原始或展开后逐权重码流
```

此前 `compile_q4k_host_base_gpu_residual.py` 生成的 high/low bitplane artifact 仍有价值：它验证了冷启动一次扫描、精确拆分和 artifact 自校验。但它现在被降级为**精确参考格式**，不能作为最终 runtime 方案，因为 host_high bitplanes 若逐 token 扫描，依然是主项权重流扫描。

“残差误差”也重新定义：完整残差保留时，位拆分合并仅有约 `1e-7` 量级浮点归约误差；此前 `0.1--0.6` 的误差都来自实验中主动把残差截成 2/3-bit，不能混入精确拆分结论。

下一轮只探索主项在冷启动被编译成部分和表或有限公式电路的方案；它允许显著增加 RAM、启动时间和运行时加法，但不允许运行时回扫主项权重。
