# Iteration 72: Five-Layer Chain and Format Boundary

Date: 2026-09-11

## Objective

Extend the same-stream resident FFN chain to five representative layers and
probe whether the zero-copy property or host submission cost degrades with a
longer dependent chain.

## Result

Report: `results/resident_device_chain_3_21_40_42_51_iter72.json`

Layers: `3 -> 21 -> 40 -> 42 -> 51`

All five layers report zero activation H2D, activation D2D, base-result H2D,
and resident-weight H2D bytes.

## Format boundary found during setup

An initial seven-layer candidate included `resident_qwen38_layer24_exact_v2`
and `resident_qwen38_layer25_exact_v2`. Those artifacts contain Q5 residual
packing, while `TiledResidentGateUp` currently accepts Q4 residual packing only.
The runner rejected the chain before timing with:

`ValueError: tiled execution currently supports Q4 residual packing only`

This is an explicit implementation boundary, not a numerical or bandwidth
failure. The five-layer measurement uses only the existing Q4 artifacts.

## Interpretation

The five-layer device span is close to the sum of the measured layer spans.
The CPU enqueue interval remains much smaller than the device span, and no
runtime weight or activation copies appear as the chain grows. This supports
the current conclusion that the tested path is kernel-time dominated.

The chain is dependency-serial: each layer consumes the previous layer's
output. Therefore these measurements do not establish concurrent execution of
different layers. Supporting Q5 residual artifacts is a separate compatibility
work item before a mixed-format long-chain benchmark can be run.
