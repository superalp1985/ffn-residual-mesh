# CUDA transfer probe

This is an isolated CUDA prototype for the FFN base/residual transport idea. It does not alter llama.cpp.

The benchmark compares:

- `base_only`: transfer only the pre-expanded base output.
- `base_plus_residual`: transfer base output plus `top-k` residual coefficients and indices, then merge against a GPU-resident residual basis.
- `base_plus_residual_overlap`: split a window into ring slots and connect copy/compute streams with CUDA events. This measures chunking overhead as well as possible overlap.
- `exact_fallback_reuse`: transfer the fallback weight page once per window, then reuse it for all tokens in that window.
- `exact_fallback_evicted`: conservatively re-transfer the full down-projection payload once per token and run a checksum kernel.

The executable accepts one optional argument: the JSON output path. The default is `results/cuda_transfer_probe_20260903.json`.

`ffn_artifact_probe.cu` is the correctness bridge to the real layer experiment. It reads a binary artifact generated by `scripts/export_cuda_residual_artifact.py`, executes the same fp16 base/residual merge on the GPU, and reports implementation error separately from approximation error against captured FFN output.

The artifact probe reports two transport layouts: `benchmarks` uses three separate H2D copies for base, coefficients, and indices; `packed_benchmarks` first combines them into one contiguous pinned packet and uses one H2D copy. Both layouts run the same merge formula, and the packed path has an independent 64-token numerical check.

The prototype uses CUDA pinned host allocation, non-blocking streams, asynchronous H2D copies, resident GPU basis vectors and residual mean, and CUDA events. Its exact fallback paths are transfer stress proxies, not complete exact FFN implementations.

Example build from PowerShell:

```powershell
nvcc -allow-unsupported-compiler -D_ALLOW_COMPILER_AND_STL_VERSION_MISMATCH -O3 -std=c++17 -arch=sm_89 D:\ffn-residual-lab\src\cuda_probe\ffn_transfer_probe.cu -o D:\ffn-residual-lab\src\cuda_probe\ffn_transfer_probe.exe
```

The compatibility defines are needed here because the installed CUDA 11.8 toolkit predates the installed MSVC STL update. The target GPU is still compiled for `sm_89`; the runtime driver is newer and exposes CUDA 13 support.
